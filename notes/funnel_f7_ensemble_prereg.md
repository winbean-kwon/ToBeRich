## 1. 대상과 보고값
논문 Table 2 (2016/01/04–2020/05/08, arXiv 2511.12120 PDF에서 확인, ICAIF '20 판의 재업로드):

| | Ensemble | PPO | A2C | DDPG | Min-Variance | DJIA |
|---|---|---|---|---|---|---|
| Cumulative Return | 70.4% | 83.0% | 60.0% | 54.8% | 31.7% | 38.6% |
| Annual Return | 13.0% | 15.0% | 11.4% | 10.5% | 6.5% | 7.8% |
| Annual Volatility | 9.7% | 13.6% | 10.4% | 12.3% | 17.8% | 20.1% |
| Sharpe Ratio | 1.30 | 1.10 | 1.12 | 0.87 | 0.45 | 0.47 |
| Max Drawdown | -9.7% | -23.7% | -10.2% | -14.8% | -34.3% | -37.1% |

- 논문 주장(5.2절): "our ensemble strategy achieves higher Sharpe ratio than the three agents, Dow Jones Industrial Average and the traditional min-variance portfolio allocation strategy."
- 논문 절차: 학습 2009/01/01–2015/09/30, 검증 2015/10/01–12/31, 거래 2016/01/01–2020/05/08. 3개월마다 성장 창으로 재학습, 3개월 검증 창으로 Sharpe 최고 에이전트 선택. 거래비용 0.1%, 초기 자산 $1,000,000. 단일 실행인지 여러 실행 평균인지 적혀 있지 않다.
- **지표 집계(저자 `backtesting.ipynb` 코드 셀):** `account_value_trade_ensemble_{i}.csv`(i = 126, 189, …, 1197의 18개)를 차례로 이어 붙이고, 앞 **1,097행**(`[0:1097]`)의 일별 수익률(`pct_change`)을 `pyfolio.create_full_tear_sheet`에 넣는다. Table 2의 행 이름은 pyfolio 성과표와 같다. 그래서 지표는 empyrical 정의로 계산한다: Sharpe = √252·평균/표준편차(ddof=1, 무위험수익률 0), 연수익 = (1+누적)^(252/행 수)−1, 연변동성 = 표준편차·√252, MDD = 누적 가치/고점 − 1의 최솟값. 논문 식 (19)의 r_f는 값이 없고, pyfolio 기본값 0을 쓴다.
- 코드의 거래 구간은 2016-01-04(번들 데이터 `unique_trade_date[63]`, 직접 확인)에서 시작해 2020-07-06 무렵까지 간다. 논문 기간 끝(2020-05-08)은 1,097행 자르기로 맞춘다(저자 방식 그대로).

## 2. 조건
**단일 조건(P = 코드 그대로).** 논문이 사이클당 스텝 수·하이퍼파라미터를 적지 않았으므로 코드 값이 유일한 기준이다: A2C 20,000, PPO 50,000, DDPG 10,000스텝, stable_baselines 기본 `MlpPolicy`, 난류 임계값 140/100/90(코드 하드코딩). 출판 후 수정(`7fbee07`, DDPG 노이즈·PPO 엔트로피)은 쓰지 않는다(F4 1절).
- 공통: 코드 @f02a762, 저장소 파일 수정 없음, F4와 같은 설치 환경(Python 3.7, TF 1.15.2, stable-baselines[mpi], 관문 통과 기록), 장치 서버 노트북 CPU(WSL2).
- 래퍼는 `train_A2C/PPO/DDPG`와 `DRL_prediction`을 감싸 시각과 **거래에 쓰인 모델 이름**만 기록한다(F4 허용 수정 1과 같은 수준, 함수 동작은 그대로). 18사이클 전부 돈다(F4의 1사이클 자르기 없음).
- 시드: 코드가 정하지 않는다. 같은 설정으로 **5회**(E1~E5) 실행한다. 래퍼는 NumPy 난수 상태 첫 값만 기록하고 설정하지 않는다. 5회로 정한 이유: RAT F7과 같은 크기이고, 논문이 실행 수를 밝히지 않아 단일 실행 값과 실행 간 변동을 구분하려면 반복이 필요하다.

### 2.1 실행 순서·재실행
- 순서 고정: E1→E5. 측정은 1회다. 설치·실행 오류나 중단일 때만 같은 실행을 처음부터 다시 돈다(같은 실행 최대 3회, 3회 모두 실패하면 '실패'로 남기고 다음으로). 결과를 본 뒤에는 재실행하지 않는다.
- 실행당 벽시계 상한 6시간(F5 A=1.12시간의 약 5배, F5 반박 검토의 과소추정 지적 반영). 넘으면 '상한 초과, 미완'이고 다시 돌리지 않는다.

### 2.2 장치·일정
- 서버 노트북 WSL2는 메모리 3.9GB이고 RAT F7(GTX 1650) 학습 프로세스가 약 2.5GB를 쓴다. 동시 실행은 메모리 부족으로 RAT를 죽일 수 있어 하지 않는다. 맥(M1 8GB)은 TF 1.15 네이티브 빌드가 없고 MARS 본 실행이 돌고 있어 쓰지 않는다.
- **RAT F7의 P 5회가 끝난 직후, R 5회 전에 Ensemble 5회를 돈다**(`funnel_f7_ensemble_after_rat_p.sh`). RAT P5 `done.json`이 생기면 rat_f7 세션을 끝내고 Ensemble을 돈 뒤 RAT 재개 스크립트로 R 1→5를 잇는다. RAT 드라이버는 P5를 끝내자마자 R1을 시작하므로, 순서 스크립트가 끊기 전 몇 초 동안 R1이 시작될 수 있다. 그 시도는 시간 기록 파일이 생겼으면 RAT 재개 스크립트가 '중단 시도'로 기록하고(시도 1회 소진), 생기기 전이면 기록이 없다. 순서 스크립트는 끊을 때 R1 폴더 상태를 로그에 남기고, RAT 드라이버와 학습 프로세스가 모두 사라진 것을 확인한 뒤에만 Ensemble을 시작한다. RAT 쪽 이탈로 RAT 결과 노트에 적는다. RAT 주 판정(P)에는 영향이 없다.
- **마감과의 관계:** P5는 2026-11-10 14시 무렵 끝날 것으로 예상한다(P1 4.55시간 기준). P5가 11-11 00:00 KST까지 끝나지 않으면 RAT P를 끊지 않고 Ensemble F7을 '미시험(일정)'으로 받아들인다(실행 스크립트가 자동으로 기록).
- **재부팅 뒤:** tmux 세션 `ens_f7`에서 순서 스크립트를 다시 띄운다. Ensemble이 다 끝났으면(`ens_all_done`) RAT를 끊지 않고 재개만 한다. 끝나지 않았으면 끝난 실행은 건너뛰고 이어서 돈다. 중단된 시도는 시작 기록(`starts.jsonl`)으로 세므로 최대 3회 규칙에 들어간다.
- 첫 실행을 2026-11-11 00:00 KST까지 시작하지 못하면 시작하지 않고 '미시험(일정)'으로 기록한다(프로토콜 3.3-4). 2026-11-25 00:00 KST 이후 새 실행을 시작하지 않는다.

## 3. 성과 열람 규칙

## 4. 판정
**R1(수치).** 완료 실행들의 Sharpe(1절 정의, 1,097행) **산술평균**이 허용 폭 안이면 통과(양측). 완료 실행 3개 이상일 때 판정, 미만이면 '판정 불가'.
- **후보 A(주 판정):** v3 규칙, 보고값과 **최고 외부 기준선**(DJIA 0.47; Min-Variance 0.45보다 높음) 차이의 절반 → 1.30 ± 0.415 = **[0.885, 1.715]**. RAT F7에서 저자 변형(RAT-B)을 빼고 최고 외부 기준선(MTL)을 쓴 것과 같은 규칙이다. PPO·A2C·DDPG는 앙상블의 구성 에이전트(같은 코드의 내부 변형)라 외부 기준선으로 보지 않는다.
- **후보 B(보조, 판정 아님):** 보고된 최고 구성 에이전트(A2C 1.12) 기준 → 1.30 ± 0.09 = [1.21, 1.39].
- **반박 심사의 반론(기록):** A의 하한 0.885는 보고된 A2C·PPO보다 낮아, 주장과 맞지 않는 수치도 R1을 통과할 수 있다. 이 문제는 R2(실행별 Sharpe > 1.12)가 따로 검사한다. B를 주 판정으로 쓰지 않은 이유: 시드 미고정 5회의 Sharpe는 실행 간 변동만으로 ±0.09를 넘길 수 있어(RAT 사전 등록에서 SR ±0.115를 판정력 없음으로 본 것과 같은 판단) R1이 수치 재현보다 잡음을 재게 된다.
- R1 지표가 v3 T3(연수익)와 달리 Sharpe인 이유: 이 논문의 주장과 모델 선택 기준이 Sharpe다.
- 누적·연수익·변동성·MDD는 R1에 쓰지 않고 값만 보고한다(Table 2의 1차 비교 지표이자 주장 지표가 Sharpe다).

**R2(주장).** 논문 주장은 "앙상블 Sharpe가 세 에이전트·DJIA·Min-Variance보다 높다"이다. 실행별 Sharpe가 보고된 기준선 최댓값 **1.12(A2C)**를 넘는 실행이 ≥⌈0.7n⌉(n=5면 4)이면 통과. 완료 실행 5개 미만이면 '판정 불가'.

**등급.** R1·R2 모두 통과 → 재현, 하나만 → 부분 재현, 둘 다 실패 → 미재현. 판정 불가가 있으면 등급은 '판정 불가'로 적고 끝난 값만 기술한다.

### 4.1 실행 전에 알고 있는 것
- 저자 노트북의 `get_daily_return`에서 `dropna()`는 주석 처리돼 있어 pyfolio에 넘기는 시리즈는 첫 NaN 포함 1,097행이다(연수익의 햇수 = 1,097/252).
- R2의 문턱(1.12)은 R1 하한(0.885)보다 높다. R1은 통과하고 R2는 실패하는 '부분 재현'이 가능한 구조다.
- 기준선은 다시 돌리지 않으므로 R2는 "보고된 기준선 대비"다. 특히 세 에이전트의 보고값은 각자 단독 전 구간 거래 결과이고 우리는 이를 재현하지 않는다.
- 검증 Sharpe로 모델을 고르는 것은 거래 구간 이전 데이터만 쓴다(시험 구간 선택 없음, RAT와 다름).

### 4.2 보조(판정 아님)
- 실행별 누적·연수익·변동성·Sharpe·MDD, 평균, R1 폭 안 실행 수, 전체 행(1,097행 자르기 없이) 기준 같은 값.
- 사이클별 선택 모델(논문 Table 1과의 일치 정도, 탐색적).
- **DJIA 데이터 점검:** 번들 `^DJI.csv`의 Adj Close, 2016-01-01~2020-06-30 중 앞 1,097행으로 누적수익과 Sharpe를 계산해 보고값(38.6%, 0.47)과 상대 차이 20% 초과면 "데이터·구간 불일치 가능"으로 표시. 판정에는 쓰지 않는다.

## 5. 고정 해석
1. 재현 → "공개 코드와 번들 데이터로 앙상블의 보고 Sharpe와 주장을 재현했다(5회, 시드 미고정)."
2. 부분 재현 → 통과한 기준과 못한 기준을 그대로 적는다.
3. 미재현이고 평균이 폭 아래 → "재현하지 못했다(보고값보다 낮음)." 폭 안 실행 수를 함께 적는다.
4. 미재현이고 평균이 폭 위 → "재현하지 못했다(보고값보다 높은 방향의 불일치)." 높은 값을 성공으로 해석하지 않는다.
