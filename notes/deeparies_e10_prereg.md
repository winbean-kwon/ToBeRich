# T1 DeepAries O1 변형 E — 10 epoch 학습(사전 등록, 실행 전 커밋)

작성 2026-10-30. O1 결과(`notes/deeparies_o1_result.md`, 미재현)를 본 뒤에 세운 질문이다. 따라서 이 실험은 O1 판정을 대체하지 않고 **변형 결과로 병기**한다.

## 1. 질문
O1 미재현이 (i) 학습 epoch 수(코드 기본 1, README 예시 10) 또는 (ii) 실행 환경(맥 vs Colab)으로 설명되는가.

## 2. 설계
- 코드·데이터·창(W0)·기록 래퍼·판정 식은 O1과 같다(`replication/deeparies_run.py`, 조건 e1·e10).
- **e10** = 원래 코드 + `--train_epochs 10`. 나머지는 코드 기본값이다(patience 3 조기 종료, lradj type1: 매 epoch 학습률 절반, 학습 끝에 검증 손실 최소 체크포인트를 불러옴).
- **e1** = 원래 코드(1 epoch). 같은 Colab 런타임에서 돌리는 환경 대조군이다.
- 시드 0–9. 실행 순서는 시드마다 e1 → e10이다. 끊기면 끝난 실행은 건너뛰고 이어서 돌린다.
- 장치는 GPU 런타임을 권장한다. 실행마다 장치를 기록한다.

## 3. 주 판정(e10, O1 기준 그대로)
- 선택 시드 = 검증 손실 최소(각 시드의 epoch별 검증 손실 중 최소, 코드가 불러오는 체크포인트의 손실).
- **R1:** |CAGR − 7.90| ≤ 0.87%p이고 ||MDD| − 13.67| ≤ 5.0%p.
- **R2:** 같은 기간 ^DJI CAGR보다 높은 시드 ≥ 7/10.
- **등급:** 재현 / 부분 재현 / 미재현.
- e1에도 같은 기준을 적용해 등급을 적는다(환경 대조).

## 4. 고정 해석 규칙
1. e10 미재현 → "README의 10 epoch 설정으로도 재현되지 않았다." 학습 epoch 부족 설명은 이 설정에서 지지되지 않는다.
2. e10이 재현 또는 부분 재현이고 e1이 미재현 → "결과가 학습 epoch 설정에 의존한다." O1 판정(미재현)은 그대로 두고 병기한다. O2(통일 프로토콜)는 이 변형으로 실행하지 않는다(계산 예산 초과). 한계로 적는다.
3. e1이 미재현이 아니면(맥 O1과 등급이 다르면) → "실행 환경이 O1 결과에 영향을 준다." 1·2와 함께 적는다.

## 5. 2차(판정 아님)
- 시드별 CAGR 짝 차이 e10 − e1: 중앙값, 양수 시드 수, 같은 장치 짝 수
- e10의 선택 epoch 분포, 조기 종료로 실제 실행한 epoch 수
- 실행 시간, 장치
- e1(Colab)과 맥 O1의 시드별 CAGR 차이

## 6. 중단·축소 규칙
- 2026-11-20까지 e10 10회가 다 끝나지 않으면 주 판정을 하지 않는다. 끝난 실행만 기술 보고한다.
- 일부 실행이 다른 장치에서 돌면 주 판정은 그대로 하고, 짝 차이 통계는 같은 장치 짝으로만 계산한다.

## 7. 알려진 한계(미리 적음)
- lradj type1 때문에 10 epoch의 학습률 합은 1 epoch의 약 3배다. epoch 1·2는 1e−5이고 이후 매 epoch 절반이다(1 + 1 + 0.5 + … + 0.5⁸ ≈ 3.0, 1e−5 단위). "10배 학습"이 아니다.
  - 그래도 이것은 README가 제시한 설정 그대로다. 학습률 스케줄은 바꾸지 않는다.
- 논문에 epoch 기재가 없으므로, 어느 결과가 나와도 "논문 설정"을 확정하지 못한다.
- 시드 선택이 검증 손실 합계 기준이라 h = 20 위주 정책 쪽으로 기운다(O1 노트). 그 특성은 그대로 둔다.
