> 사전 고정 `crypto/experiments/exposure_scale.py`(63b6cdf, 실행 전 커밋). 결과 `crypto/experiments/results/exposure_scale.csv`.
> 입력: Drive `data/crypto/rt1006/policy_paths/`(10-26 내보내기, 파일 크기 Drive와 일치). k=1 값은 `attribution_exposure_matched.csv`의 β=30 행과 일치.
> 검증(2025-10-01~12-31)·테스트(2026-01-01~07-14)는 이미 본 구간이다. 결과는 운용 참고용이며 논문 주장에 쓰지 않는다.

## 1. 사전 규칙 적용
- 검증 워밍업에서 로그 성장이 k=1(−0.08%) 이상인 k > 1이 없다(1.5: −0.52%, 2: −1.25%, 3: −3.59%, 5: −5.96%). MDD 한도 −25% 안인 k는 1~3.
- **검증 선택 k = 1 → 권고 k = 1(현행 유지).** 실행 전 예측과 같다.

## 3. 해석(반박 심사 반영)
- 사전 판정은 k=1이다. 다만 근거가 약해 **"판정 불가에 가까움"**으로 읽어야 한다.
  - 검증 1구간(3개월)으로 고른다.
  - k=1의 검증 성장이 음수(−0.08%)라 "성장 ≥ k=1" 조건이 사실상 k=1을 강제한다.
  - k=3의 검증 MDD(−24.0%)는 한도에 1%p 이내로 걸쳐 있다.
- 방향이 엇갈린다. 검증에서는 k가 클수록 나빠졌고, 테스트에서는 k=5까지 단조로 좋아졌다(MDD −18.9%, 한도 안). "노출을 키우면 나빠진다"도, "좋아진다"도 지지되지 않는다.
- 두 구간 모두 BTC가 하락한 구간이다(보유 수익 검증 −23.1%, 테스트 −28.6%). 노출 확대의 이득을 평가하기에 부적합한 표본이다.
- 검증에서 손실이 커진 기제는 비용보다 변동성 손실과 자르기다. 비용 전 수익이 k=1 +0.28%에서 k=3 −2.39%로 떨어지는데, 비용 증가분은 약 0.8%p다. 사전 예측("비용이 k배")은 기제가 틀렸다.
- 같은 노출 대안 비교(탐색적, 사후):

| 구간 | k | 정책 | 같은 노출 BTC | 같은 노출 등가중 |
|---|---|---|---|---|
| 검증 | 1 / 3 / 5 | −0.1% / −3.5% / −5.8% | −5.3% / −15.7% / −18.4% | −3.9% / −21.2% / −22.3% |
| 테스트 | 1 / 3 / 5 | +2.9% / +8.3% / +13.4% | −2.7% / −8.0% / −13.4% | +0.9% / +2.4% / +3.2% |

  - 모든 k에서 정책이 두 대안보다 낫다.
  - 노출 크기 자체의 프리미엄은 이 구간들에서 음수다. 정책의 상대 우위는 k에 비례해 커진다.
  - 우위 중 PAXG(금 연동, 정책 노출의 16~18%)·USD1(스테이블, 검증 5.6%) 비중의 몫은 분리하지 않았다. 그래서 "위험자산 노출"이라는 표현은 과대다.

## 4. 한계
- 사후 배수다. 최소주문금액·스프레드·체결 제약을 무시했다.
- 정책 입력 되먹임은 실행층에서만 배수를 곱하면 생기지 않는다. `prev_weights`는 정책 자체의 스무딩 상태이기 때문이다. 상태 파일이 재초기화될 때만 예외다.
- 실계좌에서는 반대 방향 효과가 있을 수 있다.
  - k=1이면 약 33 USDT를 종목당 하한 7.5 USDT 규칙으로 3~4종목에 집중한다.
  - k=3이면 약 100 USDT라 약 11~12종목이 되어 백테스트의 분산 포트폴리오에 더 가깝다.
  - 즉 백테스트 k=1 결과는 지금 실계좌로 그대로 옮겨지지 않는다.
- 검증 k=5의 평균 노출 72%는 초반 구간(워밍업 init 합 0.32에서 α=0.01로 감쇠)에서 합 1로 잘린 결과다(스텝의 46%). 테스트는 자르기가 없다. 검증 노출 중앙값은 10.6%다.
- 구간 2개, 둘 다 이미 본 구간이다.
- MDD 한도 −25%는 사용자 위험 선호다. 성장 조건은 Claude가 제안해, 사용자 답변 뒤·실행 전에 추가했다.
