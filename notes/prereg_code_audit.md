## 2. 점검 항목

### 2.0 대조군 (감사 시작 조건)
자체 참조 env 두 개를 먼저 만든다. 둘 다 아래 기대대로 나와야 감사를 시작한다.
- **양성 정상**: c·τ를 참조 명세대로 정확히 부과하고, 무경계 logits에 softmax를 쓴다. 기대 결과는 C1 통과, S1 비율 1.00±0.01, P1 비 상한 무한이다.
- **결함**: 비용 인자를 받지만 쓰지 않고, tanh 뒤에 softmax를 쓴다. 기대 결과는 C1 "부과 안 됨", P1 R = e².
- **보조(시점)**: 비용을 다음 스텝 가치에서 뗀다. 기대 결과는 S1 비율 1.00±0.01, 시점 "1스텝 지연".
- 구현: `replication/code_audit/harness.py`, `controls.py`, `run_controls.py` → `controls_result.json`. 커밋 시점에 세 대조군 모두 기대대로 나왔다.

### 2.1 비용
- 참조: `notes/prereg_env_conformance_v2.md` 2장의 시점 기준(새 가중치가 수익을 얻는 구간에 반영)을 쓴다.
- **판정용 크기 참조는 "양방향 비례 c·τ(현금 제외)" 하나로 고정한다.** 구현이 선언한 모형(TRF 등) 대비 비율은 기술 기록만 한다.
- **비용 상태 분류(정적 단계에서 먼저 결정)**:
  - **명시 비용**: 논문이나 설정이 c > 0을 명시함
  - **무비용 명시**: 논문이나 문서가 c = 0이나 무비용을 명시함
  - **비용 미모형**: 매개변수도 언급도 없음
- **C1 설정 반영**: 같은 스크립트 행동열을 c = 0과 c = c_test로 실행한다. c_test는 명시값이고, 명시값이 없으면 0.001이다.
  - 주 스크립트가 출력하는 보상열과 가치열이 **모두** 달라지면 통과다.
  - 둘 다 같으면 "부과 안 됨", 하나만 다르면 "부분 부과"(어느 쪽인지 기록)다.
- **S1 크기·시점**: 회전율을 아는 행동열(등가중 → 1종목 집중 → 다른 1종목 집중 → 유지)로 측정 비용 ÷ c·τ를 구한다.
  - 비율 ∈ [0.9, 1.1]이면 "정상"이다.
  - 비율이 0.5±0.02 또는 2±0.04이면 "관례 차이"(편도/왕복)이고 결함이 아니다.
  - 그 밖이면 "과소" 또는 "과다"다.
  - 시점은 "일치", "1스텝 지연", "미반영"으로 따로 적는다.
  - 행동 공간 경계 때문에 집중이 불가능하면 표현 가능한 가장 집중된 행동을 쓰고 기록한다.
- **비용 결함**: "명시 비용"인 대상에서 C1이 "부과 안 됨/부분 부과"이거나, S1 비율이 [0.5, 2] 밖(관례 차이 제외)이거나, 시점이 "미반영"인 경우다.
  - "무비용 명시"와 "비용 미모형"은 결함으로 세지 않고 따로 센다.
  - "1스텝 지연"은 기술 기록만 한다.

### 2.2 행동 매개화 (구조적 성질; "결함"이라 부르지 않는다)
- **P1 가중치 비 상한**: 배포된 주 실행 경로 전체(정책 출력 활성화 → 학습 라이브러리의 행동 처리 → env 정규화)에서 두 가중치의 최대 비 R을 유도한다.
  - 출력이 폭 Δ 구간에 묶인 뒤 softmax를 거치면 R = e^Δ다.
  - 판정은 **R 유한 / R 무한**이다.
  - 기술 기록: Δ, N, w_max, K = N·w_max.
- **경계 출처 열**: env 자체 / 학습 라이브러리(예: SB3 clip·tanh 스케일) / 정책 네트워크.
  - 동적 점검: 경계 밖 행동(각 좌표 +5, −5)을 env에 직접 넣어 env가 자르는지 기록하고, 행동 공간 안의 극단 행동으로 w_max를 잰다. 유계 활성화가 env 안에 있고 행동 공간이 실수 전체이면 극단 행동은 원시 출력 ±50으로 한다.
  - 정책 네트워크 층의 경계는 출력 활성화가 닫힌 형태의 유계 함수(tanh, sigmoid, clip)일 때에 한해 코드 행으로 판정한다.
  - 학습 라이브러리 층은 해당 라이브러리 버전의 코드 행으로 판정한다.
- **주식 수 매개화**(hmax 등)는 P1 대상이 아니다. R-매개화 분모에서 뺀다.
- **P2 초기 출발점(보조, 판정 아님)**: 공식 정책 클래스를 무작위 초기화로 5회 생성해 합성 관측 100개(표준정규, 고정 시드)에 대한 결정적 출력(평균)의 가중치를 구하고, 1/N 대비 active share(½Σ|w−1/N|)를 잰다.
  - 같은 N에서 Dirichlet(1) 무작위 가중치의 active share 중앙값을 기준선으로 함께 적는다.
  - 중앙값이 0.05 이하이고 Dirichlet 기준선보다 작으면 "1/N 출발"로 기술한다.
  - 설치가 시간 안에 안 되면 마지막 층 초기화만 정적으로 기록하고 "미측정"으로 둔다.
- 6장 단서: R이 유한해도(예: e² ≈ 7.4) 많은 배분이 가능하다. "묶였다"는 성과에 해롭다는 뜻이 아니다. 1/N 근접 주장은 P2와 저장 행동 실측이 있을 때만 한다.

## 3. 절차
1. 대조군 두 개를 구현하고 기대대로 나오는지 확인한다. 이 문서와 대조군 코드를 함께 커밋한다.
2. 표 A 순서대로 얕은 클론(코드만, `--depth 1`)을 받는다. 데이터는 받지 않는다. 저장소마다 다음을 행 번호와 함께 `notes/code_audit_static.md`에 적고 **커밋**한 뒤 동적 점검을 한다.
   - 비용 상태 분류
   - 계보
   - C1·S1·P1·P2 정적 예측
   - 동적 실행 가능성 계획(아래 4장 규칙 적용 결과)
3. 동적 점검: 합성 가격(로그정규, 고정 시드, 자산 수는 기본 설정과 같게)으로 env를 생성하고 스크립트 행동을 넣는다. 학습은 하지 않는다. 코드는 `replication/code_audit/`, 결과는 `replication/code_audit/results.json`에 둔다.
4. 정적 예측과 동적 결과가 다르면 둘 다 기록하고 동적 결과로 판정한다.

## 4. 시간·자원 제한 (고정)
- 디스크 여유가 약 1.6GB다. 무거운 의존성(대형 프레임워크, CUDA 빌드)은 새로 설치하지 않는다. 기존 `.t1env`·`.t3env` 환경을 재사용할 수 있으면 쓴다.
- 저장소당 정적 2시간, 동적 3시간이다. 실제 사용 시간을 저장소마다 기록한다. 전체 기한은 2026-11-08이다.
- 이식 규칙(모든 저장소 공통, 결과 전 고정):
  - env 계산이 numpy·pandas로 되어 있으면 그 모듈만 import한다. 필요하면 TF·torch import를 스텁으로 막는다. 코드는 고치지 않는다.
  - env 계산이 TF 그래프 안에 있거나 import가 불가능하면 **이식하지 않고** "정적만"으로 둔다.
- 시간 안에 실행되지 않은 대상은 "정적만"으로 표기한다. 정적 예측 열에 따로 적고 R 판정에는 넣지 않는다.

## 5. 반복성 판정 (신규 R 대상만, 고정)
- **R-비용**: 신규 중 **동적으로** 비용 결함이 확인된 대상이 **서로 다른 계보 2개 이상**이면 "비용 결함은 기지 대상 밖에서도 반복된다". 그렇지 않으면 "기지 대상 밖에서는 반복이 확인되지 않았다".
- **R-매개화**: 신규 가중치 매개화 대상 중 R 유한이 확인된 대상이 **서로 다른 계보 2개 이상**이면 "유한 비 상한 매개화가 반복된다". 그렇지 않으면 "반복 확인 안 됨". 확인 기준은 2.2의 층별 판정 기준이고, env·라이브러리 층은 동적 확인이 필요하다.
- 판정 문장에는 항상 m/k(구현)와 l/L(계보)을 함께 쓴다. 정적만 대상 수도 같이 쓴다.
- 이 판정은 기술 통계이며 유의성 검정이 아니다. 결과는 어느 쪽이든 그대로 보고한다.
- **사전 예측(반박 심사)**: 신규 대상 중 PGPortfolio env 계보와 #5는 비용을 부과할 가능성이 높아, R-비용은 "반복 확인 안 됨"일 가능성이 높다.
