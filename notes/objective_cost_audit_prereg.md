# 사전 등록 — 학습 목적 함수가 거래비용을 보는가 (목적 함수 수준 비용 감사, 2026-11-26)

> 상태: 실행 전. 이 문서와 대조군 코드를 커밋한 뒤에 정적 예측을 쓰고, 정적 예측을 커밋한 뒤에 동적 점검을 한다. 결과를 보고 대상·기준·분류를 바꾸지 않는다. 실패나 판정 불가도 그대로 보고한다.
> 동기(사후, 탐색적 출처): `notes/finrl_start_state_result.md` 2절에서 FinRL `PortfolioOptimizationEnv`의 EIIE·EI3 학습 손실이 비용 계수 `trf_mu`를 버퍼에 저장된 상수로 받아 행동에 대한 기울기가 0이라는 점을 판정 뒤 코드 읽기로 찾았다. 원조 PGPortfolio(`pgportfolio/learn/nnagent.py`, 기본 `loss_function6`)는 μ를 `net.output`에서 그래프 안에서 계산한다(180–201행, 기본 설정 `net_config.json` 16·32행). 이 두 사실은 실행 전에 이미 알고 있으므로 FinRL POE와 PGPortfolio는 **확인 대상**으로만 두고 반복성 판정 분모에서 뺀다.
> 반박 심사(2026-11-26) 요지: 범위를 넓히지 말 것, 손실형과 보상형 기준을 따로 고정할 것, rlportfolio 문서(FinRL POE 관련 저자)가 이미 고쳤는지 확인해 신규성을 조정할 것.

## 1. 질문
학습 신호(미분 손실 또는 RL 보상)가 설정된 거래비용에 따라 달라지는가. 평가에서는 비용을 부과하면서 학습 신호는 비용을 보지 못하는 구현이 있는가.

## 3. 점검 항목

### 3.0 대조군 (감사 시작 조건)
자체 참조 구현 세 개를 먼저 만든다. 셋 다 기대대로 나와야 감사를 시작한다(`replication/objective_audit/controls.py`).
- **손실 양성**: PGPortfolio식 손실 −mean(log(Σw·y · μ(w))), μ를 정책 출력에서 그래프 안에서 계산. 기대: 기울기 상대 차이 > 1e-3.
- **손실 결함**: 같은 손실이지만 μ를 `detach`한 상수로 곱함. 기대: 기울기 상대 차이 ≤ 1e-4(float32 수치 오차 수준).
- 커밋 시점 결과(`controls_result.json`, c_test = 0.01, float32): 양성 0.0256, 결함 2.6e-6, 보상 양성 0.0202, 보상 결함 0. 네 개 모두 기대대로. 초안의 기준(> 1e-6 / ≤ 1e-9)은 float32 결함 대조군(3.3e-6)을 판정 불가로 만들어 감사 시작 전에 아래 3.2 기준으로 바꿨다(첫 커밋 2a9b424에는 문서 치환 실패로 옛 기준이 남았고, 대상 실행 전에 이 커밋으로 정정).
- **보상 양성/결함**: 보상 = 순수익 − c·회전율 / 보상 = 총수익(비용은 가치에서만 뗌). 기대: 보상열 차이 있음 / 없음.

### 3.1 학습 신호 유형 (정적 단계에서 결정)
- **L(손실형)**: 정책 매개변수를 미분 가능한 포트폴리오 손실로 직접 최적화한다(정책 기울기식 포트폴리오 손실 포함).
- **R(보상형)**: env가 돌려주는 보상을 RL 알고리즘(SB3 등)이 쓴다.
- 둘 다면 학습 스크립트가 실제로 최적화하는 쪽으로 분류하고 다른 쪽은 기록만 한다.

### 3.2 O1 판정 기준 (고정)
- **L**: 고정 시드, 합성 가격(로그정규, 고정 시드, 자산 수는 기본 설정과 같게), 학습 스크립트의 손실 함수와 배치 구성을 그대로 써서 매개변수 기울기 g_c(c = c_test)와 g_0(c = 0)를 계산한다. c_test = 0.01로 모든 대상에 고정한다(비용 반응 여부를 보는 값이며 현실적 수준이 아니다).
  - ‖g_c − g_0‖ / ‖g_0‖ > 1e-3 → **비용 반영**
  - ≤ 1e-4 → **비용 무시**
  - 사이 값 → "판정 불가"(X)
  - 정적 기록: 비용 항이 행동(정책 출력)의 함수로 그래프에 연결되는가(행 번호).
- **R**: 회전율이 0이 아닌 고정 행동열(이전 감사의 S1 행동열: 등가중 → 1종목 집중 → 다른 1종목 집중 → 유지)을 c_test(= 0.01)와 0으로 넣고 **학습에 쓰이는 보상열**(학습 루프가 받는 값; 로깅 값 아님)을 비교한다.
  - 회전율 > 0인 스텝 중 하나라도 |r_c − r_0| > 1e-12 → **비용 반영**
  - 모두 같으면 → **비용 무시**
- 학습을 하지 않는다. 성과 수치는 산출하지 않는다.

### 3.3 분류
- **S**: 학습 신호가 비용 반영.
- **B(학습–평가 불일치)**: 학습 신호는 비용 무시인데, 같은 코드의 평가 경로(가치·보고 지표)는 비용을 부과한다.
- **N**: 학습·평가 모두 비용을 부과하지 않음(기지 결함 포함).
- **Z**: 비용 0 명시 또는 비용 미모형(결함 아님, 따로 셈).
- **X**: 시간 안에 판정 못 함("정적만"이면 정적 예측을 따로 적되 분류 수에는 넣지 않는다).

## 6. 반복성 판정 (고정, 기술 통계)
- 분모: #3–#16 중 동적으로 판정된 대상(확인 대상 #1·#2 제외).
- **R-학습불일치**: 분류 B가 **서로 다른 계보 2개 이상**에서 동적으로 확인되면 "평가에서는 비용을 부과하면서 학습 신호는 비용을 보지 못하는 구현이 FinRL POE 밖에서도 반복된다". 아니면 "FinRL POE 밖에서는 반복이 확인되지 않았다".
- 판정 문장에는 m/k(구현)와 l/L(계보), 정적만 대상 수를 함께 쓴다.
- **사전 예측**: #1 S, #2 B(사전 지식), #3·#9 N, 나머지는 예측하지 않음(정적 단계에서 적는다).

## 7. 주장 범위
- 쓸 수 있는 것: "점검한 k개(l개 계보) 공식 구현 중 m개에서 학습 신호가 설정된 비용에 반응하지 않았다(그중 b개는 평가에서는 비용을 부과)." "FinRL POE의 EIIE 구현은 원조 PGPortfolio와 달리 비용 계수를 상수로 받아 비용 기울기가 없다."
- 쓰지 않는 것: 결함이 원 논문 수치를 바꿨다는 주장(재학습 없이 모름), 분야 유병률, 저자 의도, 비용을 보는 학습이 더 좋은 성과를 낸다는 주장.
- 저장소 이슈 제기는 동적으로 확인된 B에 한해 사용자 확인 후.

## 8. 한계 (미리 적음)
- 학습 신호가 비용을 "보는가"만 판정한다. 보더라도 학습이 그 신호를 실제로 활용하는지(관성 학습 등)는 다루지 않는다(5.5의 FinRL 결과가 그 사례).
- 합성 데이터, 1인 코더, 대상 16개·계보 수 적음.
- 보상형은 보상열 차이만 본다. 할인·정규화·보상 스케일링이 비용 항을 사실상 지우는 경우(예: 매우 작은 스케일)는 기록만 하고 판정에 넣지 않는다.
- 선행: Abbade & Costa 2026(비용 모형의 현실성), Jiang et al. 2017(μ 유도), FinRL issue #340·#968(입력 무관성 사용자 보고). 동적 기울기 점검을 다룬 감사는 반박 심사 검색에서 찾지 못했다.
