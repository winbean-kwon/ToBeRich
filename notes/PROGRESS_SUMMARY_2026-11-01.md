## 1. 용어

| 용어 | 뜻 |
|---|---|
| 1/N, 등가중 | 모든 종목에 돈을 똑같이 나눠 담는 가장 단순한 전략. 이기기 어렵기로 유명한 기준선(DeMiguel et al. 2009) |
| 사전 등록 | 실험을 돌리기 전에 "이렇게 나오면 성공, 아니면 실패"를 문서로 고정하고 커밋하는 것. 결과를 보고 기준을 바꾸는 것을 막는다 |
| 탐색적 | 결과를 본 뒤 발견한 패턴. 가설을 만들 수는 있지만 증거로 쓰지 않는다 |
| O1 / O2 | O1 = 원 논문 설정 그대로 재현되는가. O2 = 통일한 공정 조건(비용 0.1%, 여러 평가 기간, 여러 시드, 매일 등가중 대비)에서 우위가 유지되는가 |
| R1 / R2 | R1 = 보고 수치가 허용 범위 안에 들어오는가. R2 = 논문의 주장(예: "기준선을 이긴다")이 성립하는가 |
| 시드 | 학습의 무작위성을 정하는 번호. 같은 코드라도 시드에 따라 결과가 달라진다 |
| 평가 시작 상태 | 평가 첫날 포트폴리오를 무엇으로 시작하느냐(현금 / 등가중 / 직전 보유). 관성이 있는 정책에서는 결과를 크게 바꾼다 |
| 미지 구간 | 2026-07-14 ~ 10-26 데이터. 한 번 평가에 썼으므로 새 가설 검증에 다시 쓰지 않는다 |
| 계보 | 코드가 어디서 복사·파생됐는지. 같은 계보의 버그는 하나로 센다 |

## 2. 단계 1 — KOSPI 주가 예측 (초기 ~ 2026-07 초)

**목표:** 한국 주식(KOSPI) 데이터로 딥러닝 예측 모델을 만들고, 그 예측으로 포트폴리오를 운용.

**데이터:** KOSPI 837종목(유효 781), 2020-01-02 ~ 2026-05-04 일봉, 기술지표 20개(`data/kospi_all.parquet`). 거시 변수 수집 스크립트(`collect_macro.py`)는 미완.

**한 일과 결과**
| 작업 | 결과 | 근거 |
|---|---|---|
| 시계열 백본 비교(MTGNN, Chronos 등) | 방향 적중률 MTGNN 0.5145, Chronos zero-shot 0.5096. 나머지도 무작위 수준. 각 1회 실행 | `backbone_results*.csv`, `extended_backbone_colab.ipynb` |
| 주파수 특징(FFT·DWT) | LightGBM AUC 0.512 → 0.525 (FFT만 쓰면 오히려 −0.003) | `freq_features_colab.ipynb` |
| DTW 클러스터링 | K=5, 한 클러스터에 299종목 몰림. 클러스터링 기간이 테스트와 겹쳐 정보 누수가 있었음(나중에 정정) | `dtw_clustering_colab.ipynb`, `methodology_report.md` |
| 클러스터 어텐션 | 클러스터 간 차이 0.001~0.003, 효과 미미 | `cluster_attn_colab.ipynb` |
| 하이브리드 임베딩 + PPO | 처음 결과 PPO +0.28% vs 등가중 +34.33%로 크게 패배. 원인은 파이프라인 결함(RevIN 누락, 피처 순서 불일치, 누수). 고친 뒤 10회 중 9회 등가중을 이겼지만, **학습 구간 평균 비중을 고정한 포트폴리오가 거의 같은 성과**(샤프 1.108 vs 1.134) | `hybrid_model_colab.ipynb`, `kospi_rerun_colab.ipynb` |
| KOSPI HRL 일반화 | 검증 샤프 1.477 → 테스트 0.137(등가중 1.038). 결함 있는 임베딩 위에서 학습 | `kospi_hrl_generalization_colab.ipynb` |

**교훈:** 예측력이 거의 없었다. RL이 등가중을 이긴 것처럼 보인 경우에도 고정 비중으로 거의 같은 성과가 나왔다. 이 시기 실험은 사전 등록 규칙을 만들기 전이라 논문에서 확인적 증거로 쓰지 않는다.

**별도 트랙:** GAPS ETF 대회(`GAPS_대회/`). 188개 ETF, Black-Litterman. 표본 밖 샤프 2.20 vs 등가중 2.35. 졸업논문과는 별개.

## 3. 단계 2 — 크립토 계층형 강화학습 (2026-07-10 ~ 10-26)

### 3.1 왜 크립토로 바꿨나
- 처음 계획은 KOSPI 분봉 + 실거래였다. 하지만 과거 분봉을 받으려면 크레온(Windows 전용)이 필요해 맥에서 불가능했다(`RL_PIVOT_SUMMARY.md` Phase 1).
- 그래서 과거 분봉과 실거래 API를 모두 맥에서 쓸 수 있는 바이낸스로 바꿨다.

### 3.2 데이터
- 바이낸스 5분봉 50심볼, 2021-01-01 ~ 2026-07-14. 정리 후 44심볼, 약 1,770만 봉(`crypto/data/features_5m/`, 2.7GB).

### 3.3 모델 변천 (`crypto/notebooks/crypto_hrl_earnhft_colab.ipynb`)

### 3.4 평가 착시 발견 (10-26)
- 원래 평가는 첫날을 **44종목 등가중 100% 보유**로 시작했다. 정책은 관성이 매우 커서(α=0.01) 그 상태에서 천천히 빠져나온다.
- 2주 워밍업으로 시작 상태를 정상화하자 β=30이 **테스트 +8.73% → +2.86%(샤프 2.60 → 1.03), 검증 +2.98% → −0.08%**로 떨어졌다.
- 4개 β 모두에서 시작 상태만으로 +2.5 ~ +5.5 로그%p가 생겼다.
- 근거: `HANDOFF_2026-10-26.md` 3장, `crypto_start_state_audit_rt1006`.

### 3.5 그 밖의 결과
| 실험 | 결과 |
|---|---|
| 미지 구간(07-14 ~ 10-26, BTC +28% 상승장) | β=30 −0.32%. 같은 노출의 BTC +2.47%, 등가중 +2.03% → 사전 판정 "우위 유지 안 됨" |
| 의사결정 주기 4시간/1일로 재학습 | 4h +2.58%, 1d −0.42%. 30분보다 낫지 않음 |
| 라우터 붕괴 | 라우터가 거의 한 에이전트만 고르는 현상이 여러 설정에서 반복. 통제 실험(32개)에서는 붕괴 0/32 → 판정 불가 |

**교훈:** 좋아 보였던 성과의 상당 부분이 평가 시작 상태 착시였다. 처음 보는 구간에서는 단순 기준선을 이기지 못했다. 여기서 "남들의 결과도 이런 착시나 평가 문제가 있지 않을까?"라는 질문이 나왔다.

## 5. 단계 4 — 검증 방법 개발 (10-26 ~ 10-27)

크립토에서 겪은 착시를 일반적인 점검 도구로 만들 수 있는지 시험했다.

| 도구 | 사전 판정 | 의미 |
|---|---|---|
| **평가 시작 상태 효과** | H1 8/8, H2 r=0.861, H3 6/6 **지지** | 관성 정책(α=0.01)에서 시작 상태가 +2.5 ~ +5.5 로그%p를 만든다. 다만 28일 창 34개에서 평균 −0.88(양수 41%)이다. 즉 결과를 한쪽으로 부풀리는 "편향"이라기보다 결과의 흔들림을 키우는 "분산"이다. 닫힌 형태 공식이 관측과 상관 0.981로 맞았지만 사후 분석이다 |
| 학습된 관성(EIIE, 크립토) | H4 지지 안 됨 | 학습된 정책은 관성이 거의 없었다(α_eff≈1). 그래서 시작 효과도 1회 비용 수준이다 |
| FinRL 공개 코드로 시작 상태 재현 | H6 지지 안 됨, H8 실질 영향 없음 | FinRL의 EIIE·EI3는 관성이 없었다. 이 구현은 수수료를 학습 신호로 쓰지 못하는 구조다(`notes/finrl_start_state_result.md`) |
| 반사실 성과 분해 | 보정 3회 모두 실패 | 정의와 합산은 성립한다. 하지만 위약 검정의 기각률이 맞지 않아(0.13) 진단 도구로 쓰지 않기로 했다 |
| 라우터 붕괴 사전 진단 | 판정 불가 | 통제 실험에서 붕괴가 재현되지 않았다(0/32). 요소 절제에서도 "라우터 요소만으로 재현 안 됨"이었다 |
| 문헌 조사 56편 | — | 상태를 가진 정책 32/56, 평가 워밍업을 둔 논문 0/56, 시작 보유 민감도를 본 논문 0/56. 1인 코딩이고 독립 재확인은 안 됨(`notes/lit/SUMMARY.md`) |

**교훈:** 시작 상태 효과는 실재하지만 평균이 0에 가까워, 단독 논문으로 내기에는 약하다(독립 검토 결론, `notes/review_next_directions.md`). 그래서 질문을 "출판된 방법들은 공정한 평가에서 버티는가"로 넓혔다.

### 6.2 결과

**T3 FinRL** (`notes/finrl_t3_o1_result.md`, `finrl_t3_o2_result.md`, `finrl_t3_o6_result.md`)

  - A2C·PPO는 매일 등가중 대비 연 −10 ~ −14%p다.

  - A2C 소실은 예측 설정에 의존한다(결정적이면 불확정, 차이 작음).

**T2 AlphaMix+** (`notes/alphamix_t2_o1_result.md`)
- O1: **미재현.** R1 1/3, R2 0/3. 시드 평균 − 등가중 차이는 −0.22 / −1.49 / −0.11%p다.
- 판정이 정의에 민감하다(탐색적).
  - 검증 성적이 가장 좋은 epoch를 고르면 '재현'이 된다. 단 S2021 차이는 +0.03%p로 사실상 0이다.
  - 논문은 어느 epoch를 보고했는지 적지 않았다.
- 학습 전 정책(e0)은 29칸 정확히 균등(1/29)이다. 학습 후에도 평균 성과는 비슷하다(탐색적).
- O5: 설정 비용을 step에서 쓰지 않는다(FinRL 파생).
- 규칙상 O2는 실행하지 않았다.

**T1 DeepAries** (`notes/deeparies_o1_result.md`, `deeparies_e10_result.md`)

- 변형 E(10 epoch, Colab T4): **미재현.**
  - e10 선택 6.38%, ^DJI 초과 3/10.
  - 1 epoch 대조군도 미재현이다.
  - → "학습이 부족해서"라는 설명은 지지되지 않는다.
- 탐색적 관찰
  - 26종목 매일 등가중 CAGR 5.20 ~ 5.78%로, 시드 중앙값 5.23%와 비슷하다.
  - 같은 시드라도 실행 환경이 다르면 3.4%p 차이가 났다(1쌍).
- O5: 비용을 과소 부과한다. 교대 행동에서 0.021배, 첫 매수 비용은 한 스텝 늦다.

### 6.3 1/N 근접 (탐색적, `notes/one_over_n_structure.md`)
- **코드 구조상:** 세 구현 모두 "범위가 묶인 출력 → softmax" 구조다. 그래서 종목 비중의 비가 e(FinRL) 또는 e²(AlphaMix+, DeepAries)를 넘지 못한다.

| 구현 | 가능한 비중 범위 |
|---|---|
| FinRL(28종목) | 1.34 ~ 9.15% |
| AlphaMix+(29칸) | 0.48 ~ 20.9% |
| DeepAries(20종목) | 0.71 ~ 28.0% |

- **저장된 가중치:** active share(1/N에서 벗어난 정도)는 다음과 같다. 최대 비중은 9% 미만이다.

| 실행 | active share |
|---|---|
| FinRL 공식 예측 | 0.19 ~ 0.24 (대부분 표본 추출 잡음) |
| AlphaMix+ 학습 후 | 0.19 ~ 0.22 |
| DeepAries 상위 20개 안 | 0.013 |

- **주장 범위:** 쓸 수 있는 것은 "재현 실행의 정책은 1/N 근방이었고, 성과는 1/N과 구분되지 않았다"까지다. "이것이 보고된 우위를 설명한다"는 주장은 하지 않는다.

### 8.2 검토 결과 요약
- **졸업논문:** 지금 결과(재현 3편 + 코드 감사)로 충분하다.
- **학술지(TMLR 등) 기준:** 약하다. 이유는 셋이다.
  - 재현이 3편뿐이다.
  - 비용 결함이 FinRL 계열 2계보에서만 나왔다.
  - 성과 분해 방법(Lo 2008)이 기존 것이다.
- **새로울 수 있는 부분**
  - 출판 방법의 공식 코드를 사전 등록 판정으로 재현했다.
  - 비용 부과를 코드 수준에서 동적으로 점검했다.
  - 짧은 검색에서는 같은 것을 한 연구를 찾지 못했다. 체계적 검색은 아니다.
- **가까운 선행연구**
  - Kruthof & Müller(FRL 2025): DRL이 1/N을 못 이긴다.
  - Yao & Zheng(2026): LLM 트레이딩 논문 30편의 서술을 감사.
  - Lo(2008): 정적/동적 분해.
  - Random Weight Guessing(2020): 학습 없는 무작위 정책 기준선.
  - Ammann 외: 크립토 생존 편향.
- **기각된 확장안**

| 확장안 | 기각 이유 |
|---|---|
| 비용 on/off 재학습 | 결과가 자명함 |
| 크립토 생존 편향 | 선점됨 |
| LLM 에이전트 시작 상태 | 겹침 위험, API 비용 |
| 실계좌 사례연구 | 체결가가 없음 |

- **일정:** MLRC 2026 마감(09-30)은 이미 지났다. 현실적인 경로는 12월 졸업논문 → 2027 TMLR 투고다.

### 8.3 학술지 수준으로 올리는 계획 (반박 심사 반영본, 사용자 확정 전)
**심사 판정:** 이 계획이면 TMLR 데스크 리젝은 피할 수 있다. TMLR은 참신성보다 "주장이 근거로 뒷받침되는가"를 본다. 남은 명백한 결함은 3개다.
1. **일반화 범위.** 56편을 어떤 검색어·DB·기간·기준으로 모았는지 기록이 없다.
   - 보완: 검색 프로토콜을 사후 재구성해 공개하고, 사후 재구성이라고 명시한다.
   - 모든 주장은 "이 표본에서"로 한정한다.
2. **코딩 신뢰도.** 사용자가 감사 설계자라서 사람–LLM 일치도(κ)는 맹검이 아니다.
   - 보완: 코딩 항목을 판단이 필요 없는 사실형으로 줄인다. 예: "본문에 비용률 수치가 있나(예/아니오), 쪽 번호, 원문 인용".
   - 인용 원문 전체를 부록에 공개하고, κ는 보조 지표로만 쓴다.
3. **"우위 없음"의 검출력.** 신뢰구간과 MDE가 없으면 "우위 없음"이 "판정 불가"로 읽힌다.
   - 보완: 블록 부트스트랩 신뢰구간과 MDE 표를 핵심 표로 올린다. 이 표가 없으면 투고하지 않는다.

**EarnMore 재현은 1주에 안 될 가능성이 크다(코드로 추정, 실측 아님).**
- 학습 규모: 2,000 episode × 128회 반복 → 시드당 수십 GPU시간으로 추정된다.
- 환경: torch 1.13, gym 0.21, pandas 1.2.4, qlib 등 옛 버전에 고정돼 있어 최신 Colab에서 설치가 깨질 위험이 있다.
- 테스트 평가 코드가 주석 처리돼 있다.
- AlphaMix+와 같은 NTU 그룹이라 계보 다양성이 늘지 않는다.
- v3의 대체 순서는 "T2 실패 시"에만 적용되므로, 새 사전 등록 부록이 필요하다.
- → 1일 파일럿으로 시간을 잰다. 시드당 10 GPU시간을 넘거나 허용 외 수정이 필요하면 "실행 비용으로 제외"로 깔때기 표에 기록한다.

**빼거나 낮출 것**
- Lo(2008) 분해: 부록 한 단락으로 낮춘다.
- κ: 보조 지표로 낮춘다.
- 실계좌 봇: 논문에서 뺀다.

| 주 | 작업 | 산출물 | 중단·축소 기준 |
|---|---|---|---|

## 9. 논문에 쓸 수 있는 문장 / 쓰면 안 되는 문장

**쓸 수 있음**
- "사전 등록한 통일 프로토콜에서 FinRL의 보고 우위는 유지 0, 소실 2, 불확정 2였다. AlphaMix+와 DeepAries의 보고 결과는 재현되지 않았다(AlphaMix+는 결과 선택 시점과 market average 정의에 따라 판정이 달라진다)."
- "FinRL StockPortfolioEnv 계보의 구현은 설정된 거래비용을 step에서 부과하지 않는다. 서로 다른 계보의 신규 구현 5개에서는 같은 결함이 반복 확인되지 않았다. MASA에서는 학습 보상에 비용이 빠져 보상과 가치가 불일치한다."
- "softmax(범위가 묶인 행동) 매개화는 가중치 비를 유한하게 묶는다. 재현 실행의 정책은 1/N 근방이었고, 성과는 1/N과 구분되지 않았다(탐색적)."

**쓰면 안 됨**
- "출판 RL 포트폴리오 결과는 일반적으로 신뢰할 수 없다." / "비용 버그가 분야에 만연하다."
- "1/N 근접이 보고된 우위를 설명한다." / "학습이 아무것도 하지 않았다."
- 미재현을 원 논문의 오류로 단정하는 문장. 데이터·환경 차이 가능성이 남아 있다.
- "학습 전 정책 대조군 / 고정 비중 분해를 처음 제안한다." 선행연구가 있다.
- KOSPI·크립토 초기 결과를 확인적 증거처럼 쓰는 것.
- 논문 문장에 커밋 해시, 실행 횟수, 감사 경위를 넣는 것.
