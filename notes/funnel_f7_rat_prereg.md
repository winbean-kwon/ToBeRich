## 0. 질문과 주장 범위
**질문.** 논문 절차(5.1절)를 저자 공개 코드(Ivsxk/RAT @d1cbe96)와 저자 공유 데이터(`Data.db`, sha256 e8a0da9e…)로 실행하면 RAT의 Crypto-A 보고 성과(Table 2)가 나오는가. 논문이 정하지 않은 설정은 코드 값을 쓴다(v3 3장, 깔때기 프로토콜 2.2).

**주장하지 않는 것.**
- Crypto-B·S&P500 결과의 재현. 저자 공유 데이터는 Crypto-A뿐이다.
- 보고값과 다를 때의 원인. 원인 후보는 보조 분석에 기술만 한다.
- 비교 기준선(EIIE·MTL 등)의 재현. 기준선 수치는 논문 보고값을 그대로 쓴다.

## 1. 대상과 보고값 (논문 Table 2, Crypto-A, 5.1절)
| | APV | SR(%) | CR |
|---|---|---|---|
| **RAT** | 156.53 ± 14.25 | 7.13 | 304.26 |
| RAT-B(저자 변형) | 25.06 ± 2.88 | 6.97 | 83.20 |
| MTL(최고 외부 기준선) | 19.69 ± 2.72 | 6.90 | 79.21 |
| EIIE | 16.04 ± 1.72 | 6.87 | 53.55 |
| UCRP | 2.37 | 4.05 | 6.32 |

- 절차(5.1절): Adam, 배치 128, 학습률 1e-4, 가중치 감쇠 1e-7, 학습 80,000스텝(암호화폐), k=30, l=5, H=2, d_f=12, 거래비용 0.25%, a0 균등. "RL 방법은 무작위 초기화 5회 평균." "±"가 표준편차인지 표준오차인지는 적혀 있지 않다.
- 지표 정의(5.1절): APV = 최종 부(S0=1), SR = 평균(r−1)/표준편차(r−1)(%로 표기), CR = APV/MDD.
- 코드의 지표(`main.py` 1089–1121, 1222–1223, 1452–1456):
  - `fAPV` = `test_online`의 누적 곱이다. 거래 시점 수는 len(test_ind) − x_window_size − 1이다. 시험 구간 첫 x_window_size개 봉에서는 거래하지 않는다. 첫 시점의 거래비용 항은 1이다.
  - `SR` = (r−1)의 평균/표준편차(torch std, 표본 표준편차)다. 비율이므로 **코드 SR × 100을 논문 SR(%)과 비교한다.**
  - `CR` = fAPV/MDD다.
  - **공매도 이자 차감:** 가중치가 음수인 자산에 `daily_interest_rate`/48(30분 봉, 코드 기본 0.001)을 곱한 음수 값을 수익에 더한다. 즉 이자를 차감한다. 논문의 APV 식에는 이 항이 없고 0.001도 논문에 없다. 논문이 정하지 않은 설정이므로 코드 값을 쓴다(§7 한계).

## 2. 조건
| 조건 | 설정 | 역할 |
|---|---|---|
| **P** | 논문 값: `total_step 80000`, `weight_decay 1e-7`, `x_window_size 30`. 나머지는 `run_main.sh` 그대로 | **주 판정**(v3 3장: 논문 절차) |
| **R** | `run_main.sh` 그대로: `total_step 50000`, `weight_decay 5e-8`, `x_window_size 31` | 병기(등급 없음) |

- 공통: 코드 @d1cbe96, `main.py` 수정 없음, 실행 래퍼(F4 허용 수정 1, pickle 수정 포함), `TZ=Asia/Shanghai`, 2016/01/01~2018/01/01, `test_portion 0.08`, 원래 시험 구간(F4의 가짜 구간 자르기 없음).
- `x_window_size`: 논문은 입력을 P_t = {P_{t−k}, …, P_{t−1}}, k=30으로 적는다. 코드의 입력은 x_window_size개 가격이다. 그래서 k=30을 x_window_size=30에 대응시킨다. 저자가 30으로 실행했다는 증거는 없다(§7).
- 시드: 코드가 시드를 정하지 않는다. 조건마다 `model_index` 1~5로 5회 실행한다. 래퍼는 실행 시작 때 `torch.initial_seed()`와 NumPy 난수 상태 요약을 기록만 하고, 값을 설정하지는 않는다. 저자 실행과 궤적이 일치하리라고 기대하지 않는다.
- **체크포인트 선택(코드 판독, F4 1절):** 코드는 1000스텝마다 시험 구간(`test_batch`, 1341–1351)으로 평가한다. 시험 포트폴리오 가치가 최대인 시점의 모델을 저장하고, 그 모델의 `test_online` 결과를 보고한다. 논문은 선택 규칙을 적지 않았다. 논문이 정하지 않았으므로 **주 판정은 코드 그대로(시험 구간 선택 포함)** 한다. 시험 구간으로 선택한다는 사실 자체를 결과로 보고한다. 선택 후보는 P가 81개(0~80,000스텝), R이 51개다.
- **보조 조건 F(판정 아님):** 학습 루프의 마지막 반복(i = total_step − 1)이 끝난 직후 래퍼가 모델을 따로 저장해 `test_online`으로 평가한다(허용 수정 4, 결과 기록). 저장은 학습이 끝난 뒤에만 일어나서 학습 난수 흐름을 바꾸지 않는다. 확정 전에 짧은 실행으로 이를 확인한다(§2.3).

### 2.1 실행 순서·재실행

- 끝난 실행의 `train_summary.csv` 행과 래퍼 기록은 지우지 않는다.

### 2.2 장치·예산

## 4. 판정(주 판정 = 조건 P)
**R1(수치).** P 실행들의 fAPV **산술평균**(논문 집계 방식)이 허용 폭 안이면 통과한다. 양측 기준이다. 허용 폭은 후보 A다(§6 결정 1).
- 후보 A(v3 규칙: 보고값과 최고 외부 기준선 MTL 차이의 절반): 156.53 ± 68.42 → [88.11, 224.95]
- 후보 B(예측구간, Patil·Peng·Leek 2016): 보고 ±를 실행 간 표준편차로 보고 1.96·√(14.25²/5 + 14.25²/5) ≈ ±17.7 → [138.9, 174.2]
- 후보 B는 보조로 함께 적는다(판정에 쓰지 않음).
- SR·CR은 R1에 쓰지 않고 값만 보고한다. SR은 실행 간 변동이나 이자 항만으로도 ±0.1%p 안팎 움직일 수 있어, v3 규칙의 ±0.115%p는 판정력이 없다고 판단했다(반박 심사). SR은 R2에서 쓴다.
- **완료 실행 3개 이상일 때 판정**하고, 미만이면 '판정 불가'다.

**R2(주장).** 논문의 주장은 "RAT가 모든 기준선보다 낫다"(5.2절)다. P 실행 중 fAPV, SR(%), CR이 **모두** 논문의 MTL 보고값(19.69, 6.90, 79.21)을 넘는 실행이 ≥⌈0.7n⌉(n = 완료 실행)이면 통과한다(n=5면 4). **완료 실행 5개 미만이면 '판정 불가'**다.

**등급.** R1·R2 모두 통과 → 재현, 하나만 통과 → 부분 재현, 둘 다 실패 → 미재현. 판정 불가가 있으면 등급을 '판정 불가'로 적고 끝난 값만 기술한다. 조건 R과 보조 F는 같은 기준으로 계산한 값을 병기하고 등급은 매기지 않는다.

### 4.1 실행 전에 알고 있는 것
- 기준선 값은 논문 보고값이다. 기준선을 다시 돌리지 않으므로 R2는 "보고된 기준선 대비"다.
- MTL APV(19.69)는 R1 허용 폭 하한보다 훨씬 낮다. 그래서 R2의 APV 조건은 사실상 통과에 가깝고, R2는 실질적으로 "SR > 6.90%이고 CR > 79.21"이다.
- 시험 구간 선택 때문에 코드의 보고 방식에는 낙관 편향이 있다. 이 편향은 R1(아래쪽)과 R2를 통과하기 쉽게 만든다.
- 저장소가 제공한 사전 학습 모델의 README 표기는 fAPV 495.28이다. 이 값은 쓰지 않는다.

### 4.2 보조(판정 아님)
- 실행별 fAPV·SR·CR·MDD·TO, 평균·범위, 허용 폭 A·B 안에 든 실행 수.
- 보조 F(마지막 스텝 모델)의 같은 값과 P와의 차이.
- 조건 R의 같은 값. P와 R은 선택 후보 수가 달라(81 대 51) 차이에 선택 효과가 섞인다.
- 선택된 체크포인트의 스텝.
- **UCRP(데이터 점검용):** 현금 포함 12자산 균등, 매 시점 재조정, 거래비용 0.25%(코드와 같은 비용식), 이자 0이다. P의 거래 시점과 같은 시점에서 시작한다. 논문 2.37과 상대 차이가 20%를 넘으면 "데이터·구간 불일치 가능"으로 표시한다. 판정에는 쓰지 않는다.

## 5. 고정 해석
1. P 재현 → "논문 절차를 공개 코드와 저자 데이터로 실행해 Crypto-A 보고 수치를 재현했다. 보고 절차는 시험 구간으로 체크포인트를 고른다."
2. P 재현이고 F(마지막 스텝 모델)가 허용 폭 밖 → 1에 덧붙여 "시험 구간 선택 없이 학습 마지막 모델을 쓰면 보고 수치에 미치지 못했다"고 적는다. F 값을 함께 적는다.
3. P 부분 재현 → 통과한 기준과 통과하지 못한 기준을 그대로 적는다.
4. P 미재현이고 평균이 허용 폭보다 아래 → "재현하지 못했다(보고값보다 낮음)." 허용 폭 안의 실행 수를 함께 적는다.
5. P 미재현이고 평균이 허용 폭보다 위 → "재현하지 못했다(보고값보다 높은 방향의 불일치)." 높은 값을 재현 성공으로 해석하지 않는다.
6. 조건 R이나 보조 F의 결과로 P의 등급을 바꾸지 않는다.

## 7. 한계(미리 적음)
- 저자가 README에서 코드가 "논문보다 몇 버전 앞서 있다"고 밝혔다. 결정 층이 다르다(헤드 2개). 조건 P도 논문 시점의 코드가 아니다.
- 코드의 공매도 이자 차감(일 0.001)은 논문 식에 없다. 이 항은 값을 낮추는 쪽으로 작용할 수 있다.
- k=30을 x_window_size=30에 대응시킨 것은 해석이다.
- 기준선은 보고값이고, 비교 대상(MTL)은 이 문서에서 정했다.
- 5회는 작은 표본이다. 시드를 고정하지 않아 다시 돌려도 값이 달라질 수 있다.
- 데이터가 논문이 쓴 것과 같은지는 저자가 공유한 파일이라는 점 말고는 확인할 길이 없다. UCRP로 간접 점검한다.
- 인용 문헌(Patil et al. 2016, Lakens 2017, Henderson et al. 2018)은 원문을 다시 확인한 뒤 논문에 쓴다.
