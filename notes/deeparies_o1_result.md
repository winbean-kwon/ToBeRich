## 2. 2차·탐색적 관찰(판정 아님)

- **시드 분포:** CAGR 평균 5.70%, 중앙값 5.23%, 범위 3.98~8.38%. MDD 중앙값 −19.4%.
  - ^DJI 대비 차이는 −3.60~+0.92%p이고, 10개 시드 중 8개가 음수다.
  - 보고값 7.90%보다 높은 시드는 1개(시드 6, 8.38%)다.
- **같은 코드·시드·분할에서 실행 환경만 달라졌을 때(탐색적):**
  - 파일럿 P2(Colab CPU 2코어, torch 2.11, `notes/deeparies_pilot_result.md`)의 시드 0 결과는 CAGR 7.42%, MDD −19.29%였다.
  - 이번 맥 실행의 시드 0은 CAGR 3.98%, MDD −17.42%다.
  - 인자(`--market dj30 --data general --is_training 1 --seed 0`)와 커밋은 같다. 두 실행에서 시드 0 결과가 3.4%p 달랐다.
  - 다만 1쌍뿐이고 원인이 분리되지 않았다. torch 스레드 수(2 vs 기본), torch 2.6 vs 2.11, Python·numpy 버전, 기록 래퍼 유무가 섞여 있다. 같은 맥에서 다시 돌려 결정성을 확인하지도 않았다.
- **등가중 대조(탐색적, 사후 계산, 무비용):**
  - 데이터 26종목을 매일 등가중으로 단순 계산한 CAGR(365일 연율화, 날짜 열 처음·끝과 같은 구간)은 다음과 같다. ~2024-11-12 기준 5.20%, ~2024-12-09 기준 5.78%.
  - DeepAries 시드 중앙값 5.23%와 비슷한 수준이다.
  - 코드의 스텝 일정(시작 20거래일 지연, h일 보유)을 따르지 않은 근사이므로 O2식 비교가 아니다.
- **^DJI 구간 민감도(탐색적, 반박 심사 계산):** 실제 노출 구간(첫 거래일~마지막 스텝 끝)으로 맞추면 ^DJI CAGR은 7.5~8.4%로 오르고, 초과 시드는 1/10(시드 6)이 된다. 사전 정의가 DeepAries에 유리한 쪽이므로 R2 미충족 방향은 구간 정의에 견고하다.
- **검증 손실 선택(탐색적, 코드 특성):** `vali()`의 손실은 스텝 평균이 아니라 합계다. 그래서 h = 20을 주로 고르는(스텝이 적은) 정책이 검증 손실 최소로 뽑히기 쉽다.
  - 손실 하위 3개(시드 2·3·9)는 h = 20 위주이고, 상위 3개(시드 4·5·8)는 h = 1 위주다.
  - R1 대역(CAGR 7.03~8.77) 안에 드는 시드는 1·6이다.
- **논문 지수 값(탐색적):** 논문의 지수 MDD 21.94%는 ^DJI의 2022년 낙폭과 같아, 평가 기간에 2022년이 들어간 것은 맞아 보인다. 그러나 지수 CAGR 6.15%는 2021-12-31 시작·365일 연율화로는 어떤 끝 날짜에서도 나오지 않는다(끝 2025-02-07이면 6.59%).
  - 252거래일 연율화와 2024-10 무렵 끝, 또는 2022-01-31 시작이면 6.15%에 가까워진다. 논문의 평가 구간이나 연율화 정의가 코드 기본값과 다를 수 있다는 단서다.
  - 우리 R2 비교 대상(^DJI 6.4~7.6%)은 논문의 비교 대상(6.15%)보다 높다.
- **공개 체크포인트(참고):** 저장소 체크포인트로 W0를 추론하면 CAGR 6.87%, MDD −12.46%다(`deeparies/logs/W0_a_s99.log`). 이 체크포인트는 2023-10까지 학습해 테스트 구간과 겹치므로(누출) 비교에 쓰지 않는다.
- **실행 시간:** 1회 121~384분이다(맥 M1, torch 스레드 2 × 병렬 4. 파일럿은 Colab CPU 2코어 단독 20분). 실행 중 맥이 약 2.3시간 잠자기에 들어가 일부 실행에 그 시간이 포함됐다.
  - 잠자기를 뺀 실측은 약 2~4시간/회(병렬 4)다.
  - v3 9장의 "1회 약 20분"은 Colab 측정값이었다. 맥에서는 그보다 훨씬 오래 걸린다.

## 3. 냉정한 해석

- 사전 기준으로 DeepAries의 논문 보고값(CAGR 7.90%, MDD 13.67%)은 코드 기본 설정의 공식 코드로 재현되지 않았다. "^DJI를 이긴다"는 주장도 10개 시드 중 2개에서만 성립했다.
- 미재현의 원인은 이 실험으로 가릴 수 없다. 후보는 다음과 같다.
  - 논문과 코드 기본 설정의 차이. 논문 5.1절에는 epoch·하드웨어 기재가 없고, 분할은 데모를 보라고만 적었다. README는 1 epoch 명령을 "Quick training"으로, `--train_epochs 10`을 "Training with more epochs"로 따로 제시한다.
  - 평가 구간·연율화 정의의 차이(위 논문 지수 6.15% 불일치)
  - 데이터·라이브러리 버전
  - 시드·하드웨어 비결정성
- 환경이 다른 두 실행에서 같은 시드가 3.4%p 달랐다. 실행 환경 민감성의 가능성을 시사하지만, 1쌍이고 원인이 분리되지 않아 주장하지 않는다(탐색적).
- 미재현은 "논문 수치가 틀렸다"는 뜻이 아니다(v3 0장). 논문 수치와 코드를 잇는 로그가 없다.

## 4. 한계

- **실행 환경:** 맥 CPU 한 환경이다. 논문의 하드웨어(미기재)·라이브러리와 다르다(requirements: numpy 1.26 등, 우리는 numpy 2.x).
- **설정:** 논문에 학습 설정이 없어 코드 기본값(train_epochs 1)을 썼다(v3 3장 규칙). README의 10 epoch 예시처럼 저자가 다른 설정을 썼다면 그 차이가 미재현을 설명할 수 있다.
- **데이터:** 저장소에 포함된 데이터는 26종목이다(티커 목록은 27).
- **선택 규칙:** 시드 선택 규칙(검증 손실 최소)은 논문 5.1절을 따랐지만, 논문의 검증 손실 정의와 같은지는 확인하지 못했다.
- **저자 문의:** 아직 하지 않았다. v3 3장에 따라, 문의하면 날짜와 응답을 기록한다(사용자 확인 후).
