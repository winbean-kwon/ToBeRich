# T1 DeepAries O4(비용 구현 영향) — 실행 범위 고정 (2026-11-11, 계산 전)

> 근거: `notes/prereg_reeval_v3.md` 5장 O4("같은 체크포인트를 원래 env와 U1 env로 평가한 로그 성장률 차이"), 계산식은 `replication/deeparies_run.py` 머리말 O2·2차 항목(실행 전 커밋, `O4 = 원래 env 기록 가치의 연율 로그 성장 − U1 c=0.0001 값(조건 (a))`)과 `cmd_judge2` 안의 O4 줄 그대로다.
> 이 문서는 판정 기준을 새로 만들지 않는다. O4는 v3 5장의 2차 결과(기술 보고)이고 판정에 쓰지 않는다.

## 1. 왜 지금 하는가
- T1 O1은 미재현이라 O2 판정은 하지 않는다(v3 4장). O4는 O2 판정이 아니라 5장 2차 결과이고, 새 학습 없이 O1 기록만으로 계산된다.
- O5에서 원래 env의 비용이 참조 명세보다 적게 부과됨을 확인했다(교대 시나리오 0.021배, 첫 매수 비용 한 스텝 지연). O4는 그 차이가 학습된 정책의 실제 경로에서 얼마인지 잰다.

## 2. 입력(이미 있는 기록, 새 실행 없음)
- 주: 맥 O1 W0 조건 (a) 시드 0–9 (`replication/deeparies/runs/W0_a_s*.csv`).
- 보조: Colab 변형 E의 e1·e10 시드 0–9 (`replication/deeparies/e10/`). e10의 다섯 시드는 e1과 같아(`notes/deeparies_e10_result.md`) 독립 표본이 아님을 함께 적는다.
- 정책은 무상태라 가중치·구간 선택은 env 비용과 무관하다(헤더 O2 항목). 그래서 같은 가중치 경로를 U1로 다시 계산하는 것이 '같은 체크포인트를 U1 env로 평가'와 같다.

## 3. 계산(고정)
- 시드마다 `expand()`로 일간 목표 행렬을 만들고 `finrl_t3_run.u1_returns(W, R, 0.0001)`로 U1 순수익을 구한다.
- O4 = (252/N)·log(원래 env 기록 가치 끝값) − (252/N)·Σlog(1+U1 순수익), %p/년. N은 펼친 행 수(첫 행 포함, judge2와 같음).
- 함께 적는 값: 시드별 O4, 중앙값·최소·최대, 리밸런싱일 평균 회전율, 펼침 점검 오차(무비용 성장 − 코드 라벨 성장 최대 오차).
- 탐색적(판정 아님, 이름에 표시): 같은 경로의 c = 0.001에서의 U1 비용 효과 — 원래 env를 c = 0.001로 다시 돌린 값이 없으므로 '원래 env − U1'이 아니라 U1 c=0.0001과 c=0.001의 연율 로그 성장 차이만 적는다.

## 4. 읽는 법(결과 전 고정)
- 판정 문턱은 없다. 시드 중앙값과 범위를 그대로 보고한다.
- 해석 문구: |중앙값| < 0.1%p/년이면 "논문 수수료(0.01%)에서는 비용 구현 차이가 연 성장률을 거의 바꾸지 않는다"로 쓰고, 결함의 존재(O5)와 영향의 크기(O4)를 구분해 적는다. 그 이상이면 크기를 수치로만 적는다.
- 금지: O4 값으로 O1 등급을 바꾸거나, '논문 수치가 비용 결함 때문'이라고 쓰는 것.
- 계산 스크립트는 `replication/deeparies_o4.py`(이 문서와 같은 커밋), 결과는 `replication/deeparies/o4.json`.
