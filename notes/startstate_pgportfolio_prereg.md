# 사전 등록 — PGPortfolio 원조의 학습된 관성과 평가 시작 상태 효과 (2026-11-28, 실행 전)

> 기반: `notes/startstate_costaware_prereg.md`(같은 질문·측정·판정). 그 실험에서 WaveCorr는 관성을 학습하지 않았고(α_eff > 0.9999) 시작 상태 효과도 없었다. RAT는 서버 디스크 하한으로 측정하지 못했다. 이번 대상은 7.1 감사에서 학습 신호가 비용에 반응한(S, 기울기 상대 차이 2.68) **PGPortfolio 원조**(Jiang et al., 2017; 서버 `~/f4work/eiie_inspect/repo`, 48cc5a4). 이 구현은 비용을 그래프 안의 μ로 학습하고 직전 가중치를 정책 입력에 넣는다는 점에서 관성을 학습할 가능성이 가장 큰 공개 구현이다. 지위: 사전 등록 기제 검정(재현 판정 아님).

## 1. 설정(고정)
- 코드: 원조 저장소 그대로, 기본 `pgportfolio/net_config.json`(구조·스텝 수·비용 0.25%·기간·자산 수). 바꾸는 것: 시드(0, 1, 2)와 측정용 평가 코드(새 파일, 원 코드 수정 없음).
- 데이터: 서버의 기존 `~/f4work/Data.db`만 쓴다. **다운로드·Poloniex 조회 금지.**
- 실행 전 관문(결과를 보기 전):
  - G1: Data.db가 기본 설정 기간·코인 선택에 필요한 30분 봉을 모두 포함한다(코드의 데이터 매트릭스 생성이 온라인 조회 없이 끝남).
  - G2: TF1 환경에서 원 코드 학습 100스텝 시험 실행이 끝난다.
  - G3: 정책 입력에 직전 가중치가 들어간다(코드 위치를 기록).
  - 하나라도 실패하면 측정 없이 "실행 불가"로 기록하고 끝낸다.
- 자원: 서버 CPU, 모델당 상한 6시간, 전체 상한 14시간(넘으면 끝난 시드만 쓰고 기록). C: 여유 2 GB 하한(감시 스크립트가 멈춤; 디스크로 중단된 시도는 횟수에 넣지 않되, 모델당 최대 2회).

## 2. 측정(기반 2절과 같음)
- 현금 = BTC(코드의 자산 0).
- α_eff: 학습 구간에서 고르게 고른 20개 시점마다, 현금 시작(BTC 100%)과 등가중 시작(모든 자산 1/m)으로 60스텝을 실행한다(온라인 학습 끔). 노출(1 − w_BTC) 차이의 누적이 Σ(1−α)^(k+1)과 같아지는 α를 구한다.
- 시작 상태 효과: 시험 구간에서 보고 지표(fAPV, SR)를 두 시작으로 평가해 차이를 본다.
  - 원래 시작: 코드의 초기 보유(BTC 100%).
  - 워밍업 시작: 시험 시작 직전 60스텝을 학습 없이 실행해 얻은 보유.
- 주 평가는 온라인 학습을 끈 결정적 백테스트로 한다. 보조로 코드 기본(rolling training 켬)도 같은 비교를 해 기술한다.

## 3. 판정(고정; 단위 = 모델)
- **H-I(관성):** α_eff < 0.5인 모델이 절반 이상(3개 중 2개 이상)이면 "이 구현은 관성을 학습했다", 아니면 "학습하지 않았다".
- **H-S(시작 상태):** |지표(원래) − 지표(워밍업)|의 중앙값이 fAPV 상대 5% 이상 또는 SR 0.1 이상이면 "보고 지표에 실질적 영향", 아니면 "실질적 영향 아님". SR은 코드의 정의를 쓴다.
- 함께 보고: FinRL EIIE·EI3(5.5)·WaveCorr 결과와의 대비. 두 판정 모두 기술적이며 유의성 검정이 아니다.

## 4. 한계(미리 적음)
- 구현 하나, 모델 3개, 암호화폐 30분 봉, 코드 기본 기간. 비용 0.25% 하나.
- α_eff는 노출(현금 대 위험 자산) 차원만 본다.
