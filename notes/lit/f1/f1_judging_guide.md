# F1 판정 예시표 (2026-11-20 추가, 17/54편 판정 도중)

`notes/f1_recheck_prereg.md`의 판정 정의는 바꾸지 않았다. 정의를 잘못 적용하는 사례가 반복되어, 그 정의를 예시로 풀어 쓴 것이다. 추가한 시점과 경위는 `f1_recheck_log.md`에 적는다.

## 순서대로 묻는다
1. **원문 PDF를 구했나?** 못 구했으면 → `원문 미확보` (메모에 이유: 유료, 링크 없음 등)
2. **논문이 코드 링크를 직접 적었나?** (본문·각주·초록·"Code is available at")
   - 링크가 열리고 저장소가 실제로 있음 → `찾음`
   - 링크가 안 열림(404, 삭제, 비공개) → `링크 사망`
3. **논문이 "요청하면 코드를 주겠다"고 적었나?** → `요청 시 제공`
4. **링크가 없으면 1저자·교신저자의 GitHub, 홈페이지, 학회 supplementary, Hugging Face 논문 페이지를 본다.** 이 논문 코드가 있으면 → `찾음`
5. **저자와 무관한 사람이 이 논문을 재구현한 저장소만 있나?** → `제3자만`
6. 어느 것도 아니면 → `없음`

## 헷갈리는 경우

| 보이는 것 | 판정 | 이유 |
|---|---|---|
| 각주·본문에 `github.com/<저자 계정>/<이 논문 이름>` | **찾음** | 논문이 가리키는 저장소다. 계정 이름이 저자 실명과 달라도 논문이 가리키면 공식이다. |
| 참고문헌에 다른 라이브러리 링크(cvxportfolio, mlfinlab, gym, FinRL 등) | 해당 없음 → 계속 진행 | 논문이 **사용한** 도구다. 이 논문의 코드가 아니고 제3자 재구현도 아니다. |
| 참고문헌에 다른 논문 링크(Nature DQN, arXiv Adam 등) | 해당 없음 → 계속 진행 | 인용일 뿐이다. |
| 1쪽 하단 "Permission to make digital or hard copies … request permissions from permissions@acm.org" | 해당 없음 → 계속 진행 | ACM **저작권 안내문**이다. 코드 요청 문구가 아니다. |
| "Code/data available upon (reasonable) request" | 요청 시 제공 | 저자가 코드를 주겠다고 적은 경우만 해당한다. |
| GitHub에서 제목으로 검색했는데 저자와 무관한 사람이 "Implementation of <이 논문>"으로 올린 저장소 | 제3자만 | 이 논문을 재구현한 것이고 저자 계정이 아니다. |
| 저자 조직(연구실·회사) 계정의 저장소, 논문 언급은 없지만 README가 이 논문을 가리킴 | 찾음 | 저자 조직 계정이다. 메모에 "논문에 링크 없음, 조직 계정"이라고 적는다. |
| 논문 링크가 비어 있는 저장소(README만 있음)로 연결 | 찾음 + 메모 "빈 저장소" | F1은 존재 여부만 판정한다. 내용은 F2 이후 단계에서 본다. |
| 20분이 지나도 결론이 안 남 | 그때까지의 판정 + 메모 "20분 상한" | 사전 등록 규칙이다. |

## URL·근거 위치 칸
- `찾음`·`링크 사망`: URL에 **저장소 주소만** 적고, 근거 위치에 "1쪽 각주", "4.1절" 같은 위치를 적는다.
- 그 밖의 판정: URL은 비워도 된다. 참고문헌 문단을 붙여 넣지 않는다.
