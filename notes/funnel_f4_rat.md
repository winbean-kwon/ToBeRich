## 2. 사전 등록 (실행 전 고정, 이 커밋)

### 2.1 성과 비노출
- 허용 수정 2(입력 데이터 자르기): 래퍼가 `HistoryManager.get_global_panel`의 원래 결과(종목 선택은 원래 종료일 기준 그대로)에서 **앞 split = (코드와 같은 식) int(0.92 × N)개 시점만** 남겨 넘긴다. N은 전체 시점 수다. 그러면 코드가 남긴 구간 안에서 다시 0.92/0.08로 나누므로 가짜 시험 구간이 원래 학습 구간 안에 놓인다. 원래 시험 구간은 판을 만들 때 메모리에 읽히고, 자르기 전 결측 채우기를 통해서만 남긴 구간에 들어갈 수 있다(2.6). 학습·평가 계산에는 쓰이지 않는다. F4·F5는 시간만 재므로 이 점과 아래 종목 선택 문제는 판정에 영향이 없다.
- 가짜 시험 구간 지표도 열지 않는다. 표준 출력(`smoke.log`, 학습 중 시험 지표를 print한다), 모델 파일, `train_summary.csv`는 열지 않는다. `train_summary.csv`는 존재만 확인한다. 오류 확인은 래퍼의 `error.log`(traceback만)와 PPN과 같은 고정 필터를 거친 `smoke_err.log`로 한다.
- 래퍼는 성과가 아닌 값만 기록한다: 시각, 선택 종목, 시점 수, 날짜 경계, 판 모양.

### 2.4 실행
- **S:** `run_main.sh` 설정, 스텝만 2001. 학습(2001스텝, 0·1000·2000스텝에 학습 중 평가) → 저장 모델 불러오기 → 최종 평가 → `train_summary.csv` 쓰기까지 전 경로.
- 벽시계 상한 3시간. 넘으면 끊는다. 상한으로 끊긴 것은 실행 실패로 세지 않는다.
- 측정은 1회다. 설치·실행 오류나 연결 끊김으로 값이 안 나올 때만 다시 돈다. A가 10시간 근처여도 재측정하지 않는다.
- 끊김 처리(PPN 2.4와 같음): 시간 표시를 60초마다 Drive에 복사한다. 다시 실행하면 끝난 실행(F4 통과 또는 상한 중단)은 건너뛴다. 끊긴 실행은 처음부터 다시 돌고, 이전 기록은 `S_times.attemptN.jsonl`로 보존한다. 끊긴 기록으로 계산한 A_lb가 10을 넘으면 다시 돌지 않고 "한도 초과(하한 기준)"로 확정한다.
- 측정값: `startup` = 프로세스 시작 → 0스텝(데이터 적재·모델 생성 포함), `block` = 1000스텝 → 2000스텝(학습 1000스텝 + 학습 중 평가 1회), `e` = 1000스텝 학습 중 평가 시간, `tail` = 학습 루프 끝 → 최종 평가 끝(모델 불러오기 + `test_online`), `t_on` = `test_online` 시간.
- 환산 비율: 가짜 시험 구간이 원래보다 짧으므로 평가 시간을 비율로 늘린다. `n_orig` = N − split, `n_fake` = 래퍼가 기록한 가짜 시험 시점 수. `r_b` = n_orig / n_fake, `r_on` = (n_orig − 32) / (n_fake − 32)(`test_online`의 전진 횟수 = 시험 시점 수 − 32).

### 2.5 판정
**F4:** S가 `rc=0`이고 학습 루프 끝·최종 평가 끝 표시가 있고 `train_summary.csv`가 생기면 통과("가짜 시험 구간 기준, 원 시험 구간 미실행"으로 표기). 상한으로 끊기면 "상한 내 미완". 실패하면 허용 수정 범위에서 고친다(대상당 벽시계 8시간 안). 끝내 안 되면 "실행 불가".

**F5(판정값 A, 논문 절차):**
A = (startup + 80 × [(block − e) + e × r_b] + [(tail − t_on) + t_on × r_on]) / 3600 시간.
- 80,000스텝 = 1000스텝 블록 80개(학습 중 평가도 80회).
- A > 10: F5 "한도 초과"(장치 표기). 다음은 Ensemble.
- A ≤ 10: F5 통과. 순서 규칙(3.3)상 F7 후보다. F7 설정(논문 80,000스텝·5회 vs 저장소 50,000스텝, 가중치 감쇠, 시험 구간 체크포인트 선택 처리)은 F7 사전 등록에서 정해야 하므로 **멈추고 사용자에게 보고**한다.
- **하한 규칙:** 최종 평가 전에 끊겨 A를 계산할 수 없으면 A_lb = (startup + 80 × block) / 3600(2000스텝 표시가 없으면 0→1000스텝 시간). 1000스텝 표시도 없이 상한에 걸리면 A_lb = 80 × 3 = 240시간. A_lb > 10이면 "한도 초과(하한 기준)", A_lb ≤ 10이면 "F5 측정 실패".
- **일반 규칙(PPN과 같음):** 논문이 정한 항목(스텝, 배치)은 논문 값, 논문이 정하지 않은 항목은 저장소 값.

**참고값 B(판정에 쓰지 않음, 저장소 50,000스텝):** B = (startup + 50 × [(block − e) + e × r_b] + [(tail − t_on) + t_on × r_on]) / 3600.

**탐색적 기록:** GPU 이용률·메모리, CPU 시간 비율, 첫 블록 시간, 데이터 적재 시간, 선택 종목.

### 2.6 한계(실행 전)
- 2000스텝으로 80,000스텝을 환산한다. 스텝당 시간이 일정하다고 가정한다.
- 평가 시간은 시험 시점 수에 비례한다고 가정한다.
- 논문 5회 평균은 시드당 시간에 반영하지 않는다(F5는 시드당).
- 논문은 Tesla P40에서 학습했고 시간을 보고하지 않았다.
- `panel_fillna("both")`는 자르기 전에 전체 구간에서 앞뒤 채우기를 한다. 남긴 구간 끝까지 이어지는 결측이 있으면 원래 시험 구간 값이 채워질 수 있다. 시간 측정에는 영향이 없다.
- `reindex`로 자른 판은 원본과 메모리 배치가 다를 수 있다.
- 종목 선택은 원래 종료일 기준(2017-10-04~11-03 거래량)으로 그대로 두므로, 가짜 시험 구간(남긴 구간의 마지막 8%, 2017-09 중순부터) 안의 거래량을 보고 고른 종목이다. 가짜 시험 지표는 열지 않으므로 시간 측정에는 영향이 없다.
- `main.py` 13행이 `CUDA_VISIBLE_DEVICES="1"`을 덮어쓰므로 래퍼는 정의 부분 실행 뒤(CUDA 초기화 전)에 다시 정한다.
