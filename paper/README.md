# 논문화 작업 폴더

이 폴더는 크립토 HRL 트랙(`crypto/notebooks/crypto_hrl_earnhft_colab.ipynb`, `crypto_earnhft_btc_colab.ipynb`)과
KOSPI 트랙(`progress_report_final.md`)의 결과를 논문 투고 가능한 형태로 확장하기 위한 기획 문서를 모아둔 곳이다.
실험 자체는 각 트랙의 Colab 노트북에서 계속 진행하고, 여기는 "무엇을 더 채워야 하는지"와 "지금까지 나온 결과를
어떤 서사로 묶을 것인지"를 정리한다.

## 왜 이 방향인가

당초 목표로 언급된 NeurIPS/ICML/KDD 중, 메인 트랙 기준으로는:
- **NeurIPS/ICML 메인 트랙**: 새로운 알고리즘/이론 기여가 기본 요구치라 이번 프로젝트 하나로는 현실적이지 않음.
- **KDD 응용 트랙(Applied Data Science) / ACM ICAIF(AI in Finance) / 관련 워크숍**: 지금 하고 있는 작업의
  성격(실증적 사례 연구, 실패 모드 분석, 강건성 진단)과 잘 맞고 현실적인 타겟.

**일정**: NeurIPS(~5월)/ICML·KDD(~1~2월) 2026 사이클 마감은 이미 지났다. 다음 기회는 **2027 사이클**
(ICML/KDD는 내년 초, NeurIPS는 내년 5월) — 11월 졸업 프로젝트 마감 이후 다듬을 시간과 맞아떨어진다.
정확한 마감일은 각 학회 공식 CFP에서 확인 필요(추측 금지).

## 핵심 서사

지금까지 나온 결과의 가장 강한 논문 가치는 **최종 수익률 숫자가 아니라, EarnHFT류 계층적 RL을
"연속·다자산 포트폴리오" 액션 공간에 이식할 때 어떤 실패 모드가 순차적으로 나타나고, 어떻게 진단·수정
했는가**이다. `crypto/PROGRESS.md`, `RL_PIVOT_SUMMARY.md`, 그리고 이 세션에서 나온 §14~§16(2026-07-29)
결과를 관통하는 한 줄 요약:

> Q-teacher(Stage I) 없이 EarnHFT를 연속 포트폴리오에 이식하면 다양성이 붕괴한다(v3) → 행동 공간
> 자체를 구조적으로 바꾸면(top-K 희소선택 + 리스크게이트, v4) 다양성은 회복되지만, 이번엔 그 위에
> 얹은 상위 라우터가 학습·서빙 정합성을 맞추는 과정에서 상수함수로 붕괴할 수 있다(§15) — 그리고 이
> 붕괴는 valid/test 성적 낙차라는 형태로 신호가 남아, 사후에 "이 결과가 진짜 알파인지 우연인지"를
> 가르는 강건성 진단 방법론 자체가 하나의 기여가 된다(§16, β=30 vs β=-30 비교).

보강 — 다만 이 확인 자체도 v3(EarnHFT 계열) 안에서만 이뤄졌다는 한계는 8장에 정직하게 유보로
남겨둠(Option-Critic 등 다른 HRL 계열로의 반복은 미착수).
**How to apply**: "이거 그냥 튜닝 실패 아니냐" 류 질문에는 이제 4.3절의 λ-스윕(스피어만 ρ
+0.4→-0.4→-0.8) 결과로 답할 것 — 다만 "완전히 해소됐다"고는 말하지 말 것(v3 계열 안에서의
확인일 뿐, 다른 HRL 계열 반복은 여전히 없음).

## EarnHFT 선정 근거 보강 + DQN/DDQN 불일치 발견·수정 (2026-08-14)

사용자가 "왜 하필 EarnHFT냐"를 반복 질문 → background agent로 EarnHFT 원 논문 Table 2를 직접
확인(PPO/DQN 단일정책 베이스라인이 EarnHFT 자기 세팅에서도 종종 마이너스 수익률, EarnHFT가
승리)해 1.2절에 인과적 선례로 반영. 이어서 "이 장르에 다른 논문 많을 텐데 왜 EarnHFT?"라는
재질문 → HRPM/MetaTrader/AlphaMix/DeepScalper/MacroHFT/ArchetypeTrader(AAAI'26, 실존 확인)까지
6개 동종 논문을 조사한 결과 **DP 기반 Q-teacher(KL증류)를 쓰는 건 EarnHFT가 유일** — 2.1절에
"임의의 대표사례가 아니라 절제실험 대상으로 유일한 후보였다"는 근거로 반영. 다만 사용자가 이후
"Q-teacher를 세 번이나 우려먹는다"고 지적 → 실제로 EarnHFT를 이식할 때부터(v1) Q-teacher(Stage
I)는 애초에 이식 대상에서 제외됐었다는 걸 명확히 하고, Q-teacher 언급을 선정근거·4.3절 진단·
λ스윕 세 곳에 흩어놓지 않고 최소화하는 쪽으로 서술 정리.

**사용자의 코드 직접 검증 요구에 대응해 실제 버그 하나 발견**: "라우터 상수함수 붕괴가 구현
버그 아니냐"는 질문에 실제 라우터 코드(`MacroRouterEnv`/`MacroRouterEnvV4`, action indexing)를
직접 열어 확인 — 인덱싱 자체는 단순하고 문제없었으나, 그 과정에서 **2.4절 텍스트가 "DDQN을 쓴
EarnHFT 선택을 따랐다"고 주장하면서 실제로는 표준 DQN(Mnih et al. 2015)을 인용·구현하고 있던
불일치를 발견**(EarnHFT 원 논문은 Stage I·III 모두 DDQN 사용). 텍스트를 "EarnHFT의 선택에서
벗어난 단순화"로 정정하고, 8장 한계#3에 "표준 DQN의 과대추정 편향이 라우터의 조기 단일행동
수렴에 부분적으로 기여했을 가능성을 배제 못 함 — DDQN 재학습 검증 미착수"를 추가(영/국문
동기화). 사용자 요청으로 "4개 프레임워크 중 검증/테스트 진단 없음"이라는 주장이 2.6절 비교표
4개에만 근거한 좁은 사실이지 "이 분야 전체" 일반화가 아니라는 점도 재확인함.

**How to apply**: "왜 EarnHFT" 질문 시 이제 1.2절(원 논문 자기증거)+2.1절(Q-teacher 유일성) 둘 다
근거로 답할 수 있음.

## §22 DDQN 재검증 실행 완료 — 라우터 붕괴가 알고리즘 탓이 아님을 확정 (2026-08-15)

`crypto_hrl_earnhft_colab.ipynb`에 §22(SB3 DQN 소스 직접 대조해 구현한 `DoubleDQN` 서브클래스 +
매칭 라우터 재학습) 신규 추가 후 Colab 실행 완료(라우터 학습 약 30분). 로컬에서 온라인/타겟망을

뒤 노트북에 반영. **결과: DDQN도 valid·test 양쪽에서 β=30 하나에 100% 수렴**(valid 92/92 청크,
test 195/195 청크), 순수익·샤프비율도 원래 DQN 매칭 라우터와 **소수점 둘째 자리까지 완전히
일치**(valid -0.19%/샤프 0.025, test +7.48%/샤프 3.046) — 과대추정 편향을 교정하는 알고리즘으로
