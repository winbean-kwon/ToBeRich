## 0. 배경 — 왜 계층적 RL인가

- KOSPI 트랙: Chronos+MTGNN 임베딩 기반 단순 PPO(5클러스터 상태공간, 325차원)가 테스트에서
  총수익 +0.28% vs 등가중 +34.33%로 대실패(`progress_report_final.md` §2.4). 원인 후보: 상태공간
  과부하, 보상 노이즈, 분포 이동, 임베딩 품질 미검증, 거친 액션 공간(클러스터 단위).
- 크립토 트랙: 동일 구조의 단일 PPO(44종목, `crypto_rl_trading_colab.ipynb`)도 테스트(2026-01~07)에서
  총수익 -75.68%(Sharpe -4.209, MDD -79.04%)로 실패. 등가중은 +2.66%.
- → **두 자산군에서 공통적으로, 순수 단일 정책 RL이 포트폴리오 배분에서 반복적으로 실패**한다는 것이
  계층적 구조(EarnHFT류) 도입의 실증적 동기.

## 1. v1 — EarnHFT 직접 이식 (Stage A 레짐분할 + Stage B 4β 풀 + Stage C DQN 라우터)

- 결과: 비용 후 -32.24%. 진단: 스텝당 평균 턴오버 5.4%, 누적 비용 드래그 -39.81% — **비용 전
  역산 알파 +12.6%로 이미 등가중을 이김**. 즉 신호는 있는데 30분 단위 리밸런싱 비용이 전소시킴.
- **수정 — 추론 시 관성 스무딩**(재학습 없이 `w_new=(1-α)w_old+α·softmax(a)`): α=0.01에서
  비용 후 +11.05%, Sharpe 0.638, MDD -36.47%. 비용 전 알파가 α와 무관하게 12.5~12.6%로 거의
  불변 → 신호는 수일 단위 저빈도.

## 2. v2 — 스무딩을 학습 환경에 내장

- 동기: 매 스텝 근사가 아니라 애초에 저회전 정책을 학습시키면 더 낫지 않을까.
- 결과: **실패**. 비용 후 -3.58%, 비용 전 알파도 12.6%→0.92%로 소멸.
- **핵심 교훈**: "학습은 전권(α=1)으로, 실행 단계에서만 관성을 걸어야 한다" — 관성을 학습 환경에
  내장하면 행동→보상 연결이 희석돼 PPO credit assignment가 무너짐. 부정적 ablation으로 보고 가치 있음.

## 3. v3 — EarnHFT 원문 충실 재구현 (현금 액션 + Stage II/III 논문식 valid 선별)

- 방법: 현금을 45번째 액션으로 추가, 2025년을 train(1~9월)/valid(10~12월)로 엄격 분할해 테스트
  선택 편향까지 제거.
- 결과: **실패**. 비용 후 +0.68%, 등가중(+2.65%)에도 미달. 현금 비중이 테스트 전 구간 2.2%(=1/45
  균등)로 고정 — 20개 후보 에이전트의 레짐별 성적 차이가 1%p 미만(전부 클론).
- **핵심 교훈**: EarnHFT의 다양성은 Stage I(DP Q-teacher)가 β를 지도 신호로 직접 주입하기 때문에
  생긴다. β를 데이터 샘플링 우선순위로만 쓰면(목적함수 불변) 45차원 연속 액션 PPO에서 다양성이
  자연 발생하지 않는다 — **Q-teacher 없는 EarnHFT는 연속·다자산 포트폴리오 세팅에서 원리적으로
  다양성 엔진이 없다**는 부정적 결과.

## 4. v4 — FreQuant top-K 희소선택 + DeepClair 리스크게이트 (Stage I 우회)

- 방법: 44차원 연속 softmax 대신 top-K(=10) 종목만 뽑아 그 안에서 배분(FreQuant) + 종목 선택과
  분리된 전용 리스크게이트 ρ(DeepClair)를 저수준 행동 공간에 구조적으로 이식.
- **다양성 진단 통과**: ρ 표준편차 0.068(v3는 사실상 0), β별 평균 ρ 0.109~0.545로 뚜렷한 분리,
  top-10 종목이 테스트 기간 44개 중 33개에 걸쳐 회전 — v3의 "균등가중 수렴"이 재발하지 않음을 확인.
- 성능: raw(스무딩 없음) 비용 전 알파 -0.60%로 사실상 0 — 원시 저수준 정책 자체는 v1보다 약함.
  스무딩(α=0.01) 적용 시 비용 후 +8.26%, Sharpe 2.168, MDD -5.22% (v1+스무딩 +11.05%/0.638/-36.47%
  대비 총수익은 낮지만 Sharpe·MDD 훨씬 우수).
- **정적 포지션 아티팩트 진단**(저턴오버 결과가 "초반에 우연히 잡은 포지션이 그대로 버틴" 것인지
  확인): 턴오버가 끝까지 죽지 않고(뒤10% 평균 0.088%, 0인 스텝 0%), 전반부(+5.47%)·후반부(+2.64%)
  모두 양수, 종목 선택 자카드 유사도 0.26(낮음=회전 활발) — **순수 아티팩트는 기각**, 다만 전>후반부
  수익 편중은 남은 의심으로 기록.

## 5. §13-I — episode_progress 학습·서빙 불일치 "매칭" 라우터 (2026-07-28)

- 문제 인지: 원본 v4 라우터는 학습 시 "에피소드 내 진행률"(t/len(episode))을 관측값에 포함하는데,
  라이브에는 에피소드 끝이 없어 이 값을 상수 0.5로 근사해야 함 — 학습·서빙 입력 분포 불일치.
- 수정: 학습 때도 이 값을 상수 0.5로 고정한 "매칭" 라우터(`router_v4_matched`)를 재학습(Stage B는
  재사용, Stage C만 재학습).
- 결과(단일 실행): 비용 후 8.26%→7.48%(소폭 하락), Sharpe 2.168→3.046, MDD -5.22%→-3.33%(개선).
  → 이 시점엔 "학습·서빙 정합성을 맞추니 리스크 조정 성과가 개선됐다"고 해석하고 채택.

## 6. §14 — valid 기반 재검증 (α 선택 편향 제거 시도)

- 문제 인지: 지금까지 `BEST_ALPHA_V4`류 하이퍼파라미터가 전부 **test set에 직접 돌려서** 선택된
  것 — 순수 아웃오브샘플 성능이 아님.
- 2025 Q4를 valid로 분리해 재확인:
  - **매칭 라우터의 β 선택 분포가 valid·test 모두 β=30 하나로 100%** — 이전에 원본 라우터에서
    봤던 "-30/30 절반씩" 분포는 매칭 이전 버전 얘기였고, 매칭 라우터는 사실상 라우팅을 안 함.
  - α를 valid에서 선택하면 valid 총수익 **-0.19%**(거의 손익분기) — 학습 인접 구간에서마저
    플러스를 못 냄.
  - valid에서 고른 α가 test에서 고른 α와 우연히 같아(둘 다 0.01) "편향 제거" 비교표 숫자는
    안 바뀜 — 이건 검증 통과가 아니라 우연의 일치임을 명시해야 함.

## 7. §15 — 결정적 확인: 매칭 라우터 = 상수함수

- β=30 풀 에이전트를 **라우터 없이 단독** 실행한 결과가 valid·test 둘 다 매칭 라우터 결과와
  **소수점까지 정확히 일치**(valid -0.1938% / test +7.4776%, 둘 다 "일치: True").
- **결론**: §13-I에서 "매칭 라우터가 Sharpe를 개선했다"고 본 것은 라우터가 똑똑해진 게 아니라,
  **판단을 포기하고 우연히 성적 좋은 고정 에이전트(β=30) 하나에 학습이 수렴(붕괴)**한 것이었다.
  4β 풀·DQN 라우터·macro 관측값 전체가 이 시점 기준 β=30 하나를 상수로 고르는 것과 기능적으로 동일.

## 8. §16 — 4β 전부 단독 비교: "β=30만의 문제" vs "레짐 차이" 판별

| β | valid(2025 Q4) 총수익 | valid Sharpe | test(2026 H1) 총수익 | test Sharpe |
|---|---|---|---|---|
| -90 | +2.23% | 0.416 | +4.74% | 0.600 |
| **-30** | **+4.54%** | **1.314** | **+5.66%** | **1.156** |
| 30 (구 배포) | -0.19% | 0.025 | +7.48% | 3.046 |
| 90 | -16.68% | -0.779 | -23.00% | -1.063 |
| 등가중 벤치마크 | -29.57% | -0.444 | +2.66% | 0.367 |

- β=90은 valid·test 둘 다 참패(레짐과 안 맞는 정책, 일관되게 설명 가능한 실패).
- β=-90/β=-30은 valid·test 둘 다 안정적으로 양수 — **특히 β=-30은 Sharpe가 1.314→1.156으로
  거의 유지**되는 가장 강건한 패턴.
- β=30만 valid Sharpe 0.025 → test Sharpe 3.046으로 극단적으로 튐 — **"레짐 차이" 가설은 기각**
  (다른 β들은 이런 낙차가 없음), β=30의 test 성적은 과적합/우연에 가깝다는 결론.
- **방법론적 함의(논문 기여 후보)**: valid/test 간 성적 낙차의 크기 자체가 "이 결과를 얼마나
  신뢰할 수 있는가"의 진단 지표로 쓰일 수 있다 — 단일 최고 test 성적을 보고하는 관행에 대한
  구체적 반례.

테스트한 모든 전략·모든 시드를 통틀어 최대치**로, β=30(§16)에서 봤던 "test 구간 우연" 패턴의 가장
극단적인 사례다(valid에서는 등가중보다 살짝 나은 정도였다가 test에서 폭발). **β=-30 RL은 유일하게
valid·test 둘 다 일관되게 양의 Sharpe를 내는 전략**(낙차 0.158, 최소).

**MVO는 두 구간 다 등가중과 비슷하거나 더 나쁜 완전한 실패** — 고상관 크립토 자산군에서 공분산
기반 최적화가 거의 가치를 못 더한다는 정직한 negative result.

**논문 서술 방향**: "raw 수익률 최댓값"이 아니라 "valid·test 낙차가 작으면서 동시에 양의 성과를
내는 전략"을 성공 기준으로 명시 — 이 기준에서 RL이 테스트한 5개 전략(등가중/B&H/모멘텀/MVO/RL)
중 유일하게 통과한다는 것이 "왜 RL이 필요한가"의 핵심 증거가 된다. (EarnHFT 원문 그대로의 비교는
BTC 단일자산 트랙 §10을 인용.)

## 12. §16 — Deflated Sharpe Ratio 적용 (walk-forward 대체, 2026-07-29)

**배경**: walk-forward(§1.2)가 유니버스 나이 문제로 데이터 구조상 불가능함이 밝혀져(현재 44종목
중 2022년 이전 상장 23/44뿐), 대신 Bailey & López de Prado(2014)의 Deflated Sharpe Ratio를
6개 시드(§10) 결과에 적용.

**결과**: seed=42(배포, test Sharpe 1.156) DSR=0.533, seed=11(raw Sharpe 최댓값 2.567) DSR=0.866
— **사전 예측("최댓값 시드는 다중검정 보정으로 더 낮게 나올 것")이 틀렸음이 실행 후 확인됨.**

**정정된 해석**: SR*(다중검정 보정 문턱)는 6개 시드 전체에서 공통으로 정해지는 값이라, DSR은
"최댓값을 골랐다는 사실"을 벌주는 게 아니라 "각 후보 자신의 Sharpe가 공통 문턱을 넘는가"만 본다
— raw Sharpe가 큰 seed=11이 같은 문턱을 더 쉽게 넘어 DSR도 더 높다. **다중검정 보정 ≠ 최댓값
페널티**라는 것이 이 실험에서 실증적으로 드러남(방법론 자체를 다루는 논문이라면 이 정정 과정
자체도 서술 가치 있음).

**중요한 함의**: DSR은 **단일 기간(test) 안에서 N개 전략을 시도한 것**만 보정하고, valid→test
낙차가 잡아내는 **"기간이 바뀌면 뒤집히는" 종류의 과적합은 전혀 반영하지 않는다** — 두 진단은
상호보완적이며 하나가 다른 하나를 대체하지 않는다. 실제로 두 시드 모두 관습적 유의수준(DSR>0.95)에
못 미쳐 "다중검정 보정 후 확실히 유의하다"고 할 수 있는 시드는 없음 — 배포 결정의 근거는 여전히
valid→test 일관성(§8의 낙차 비교, seed=42 최소 0.158)이 더 강함. **논문 서술 방향**: raw 수익률
크기(모멘텀 §11과 동일 교훈)와 통계적 유의성(DSR)과 기간 간 일관성(§8) 셋을 구분해서 각각 무엇을
보정하고 무엇을 못 하는지 명시하는 것 자체가 방법론적 기여.

미실행 후속: valid 기간 수익률로도 DSR 계산 시 이번엔 seed=42가 seed=11을 앞설 것으로 예상(valid
에서는 seed=42 Sharpe가 더 큼) — valid-DSR과 test-DSR을 나란히 제시하면 "단일 지표로 줄세우기의
함정"을 더 명확히 보여줄 수 있음.

## 14. `crypto_eiie_baseline_colab.ipynb` — EIIE 베이스라인 (2026-07-29)

**방법**: EIIE(Jiang, Xu, & Liang, 2017, arXiv:1706.10059) 네트워크 토폴로지(자산별 shared CNN
평가기 + Portfolio-Vector Memory + 현금 편향 → softmax 비중)를 이 프로젝트의 PPO 파이프라인에
이식(원 논문의 OSBL 학습법은 대체). 임베딩 없이 원시 OHLC 가격 윈도우만 사용, β=-30과 동일 버킷·
비용·학습예산(100k 스텝)으로 공정 비교.

| | test 총수익 | test Sharpe |
|---|---|---|
| 등가중(이 노트북 재계산) | +1.59% | 0.330 |
| **EIIE(PPO 학습)** | +0.18% | 0.275 |
| β=-30 RL(배포, 참고치) | +5.66% | 1.156 |

**핵심 발견**: EIIE가 등가중과 사실상 동일한 성적(valid에서 -31.59% vs -33.32%, test에서 +0.18%
vs +1.59%) — **균등가중으로 수렴한 정책**으로 보이며, 이는 v3(§3)에서 겪었던 "다양성 없이
균등가중 수렴" 문제가 **다른 논문의 아키텍처(EIIE)에서도 재현**된 것으로 해석할 수 있다 — 이
프로젝트만의 특수한 실패가 아니라 이 도메인(크립토 다자산)·이 학습 예산에서 흔한 함정이라는
방증. **β=-30(배포)이 EIIE를 Sharpe 기준 약 4배(1.156 vs 0.275) 차이로 압도** — 임베딩(Chronos+
MTGNN)+top-K 희소선택+관성 스무딩이라는 이 프로젝트의 설계가 표준 RL 포트폴리오 베이스라인
대비 실질적 가치를 더한다는 직접 증거.

**주의(파이프라인 정합성)**: 이 노트북은 `crypto_rl_embeddings.h5`에 의존하지 않고 독자적으로
버킷을 구성해서, 등가중 참조값이 다른 노트북들(-29%대)과 다소 차이남(-33.32%) — 원인은 버킷
구성 파이프라인 차이로 추정(정확한 원인 미조사, 우선순위 낮음). 결론(EIIE≈등가중, 둘 다 β=-30에
크게 못 미침)에는 영향 없음 — 논문에는 각주로 명시.

**한계(노트북에 명시된 간소화)**: 원 논문의 OSBL(기하분포 배치 샘플링 + 미분가능 백테스트 직접
최적화) 대신 PPO로 학습 — "EIIE 네트워크 토폴로지 + 우리 PPO"이지 EIIE 논문의 완전한 재현은 아님.

## 17. top-K 스윕 — 배포값 K=10이 임의 선택이 아니었음을 확인 (2026-08-05)

정확히 일치하지 않는다는 점은 남는다.

**부수 진단(§17-A, 스피어만 IC)**: top-K 선택의 근거가 되는 종목별 확신도 로짓과 실제 실현 수익률의

순위를 예측한다는 증거는 거의 없다** — top-K 구성에 따른 성과 차이는 정교한 종목 선별이 아니라
리스크게이트(ρ)의 노출 조절이나 포트폴리오 분산효과 같은 다른 경로에서 온다고 보는 편이 더 정확하다.
이는 지금까지 "FreQuant 응용 = 스마트한 종목 선별"로 서술해 온 부분에 대한 negative result로, 논문
Limitations에 반영할 가치가 있다.

## 20. KOSPI HRL 일반화 검증 — 부정적 결과, 진단 방법론이 의도대로 작동함을 보여줌 (2026-08-06)

`kospi_hrl_generalization_colab.ipynb`(신규, 저장소 루트) 실행 — 크립토의 최종 레시피(Q-teacher

KOSPI 5클러스터 환경에 이식한 축소 버전. 2023년을 학습에서 완전히 제외해 진짜 미노출 valid로,
test(2024-2025)는 기존 단일 PPO 베이스라인(`rl_trading_colab.ipynb`, +0.28%/Sharpe 0.100)과

**§7 다양성 진단**: v3처럼 전면 붕괴는 아님 — β=30이 나머지 셋과 비중 궤적 상관 0.22~0.51로

**§8 스무딩 스윕**: 크립토와 다른 방향으로 나타남 — β=-30만 저α(0.01~0.03)가 valid 최선이고,
β=-90/90은 오히려 고α(0.3, 스무딩 약함)가 valid 최선. "관성이 항상 이긴다"는 크립토 결론이
그대로 옮겨오지 않음 — 일봉 주기라 30분봉 리밸런싱 같은 고빈도 잡음이 원천적으로 없기 때문일
가능성.

**§9 최종 비교(핵심)**: valid Sharpe 기준 자동 선택된 β=90·α=0.3이 **valid에서는 등가중을
이겼지만(Sharpe 1.477 vs 1.306, +26.68% vs +17.60%) test에서는 참패**(Sharpe 0.137 vs 등가중
1.043, +1.57% vs +34.33% — 원본 단일 PPO의 Sharpe 0.100과 비슷한 수준). valid→test 낙차가 이
프로젝트에서 관측된 것 중 가장 큰 축(그것도 크립토 β=30·모멘텀과 반대 방향 — valid는 좋았는데
test에서 무너짐).

**해석**: 이 프로젝트 자신의 진단 기준(valid/test 일관성, §4.6/§16)으로 보면 이 KOSPI HRL 후보는
명백히 기각 대상이다 — **"크립토의 레시피가 KOSPI에 그대로 옮겨붙지 않는다"는 것을, 크립토와
동일한 엄격한 잣대로 스스로 잡아낸 결과**. 헤드라인 valid 수치만 봤다면 배포했을 후보를 같은
방법론이 걸러낸 사례라, 실패가 아니라 진단 방법론이 의도대로 작동함을 보여주는 증거로 프레이밍
가능. 동시에, 등가중·원본 단일 PPO 둘 다 이 KOSPI HRL 후보를 이겼다는 것은 "크립토와 달리 KOSPI
에서는 아직 어떤 RL 계열도 등가중을 못 이긴다"는 뜻이기도 하다 — 7장의 "한 시장만이 뒷받침하는
것" 문단이 이제 가설이 아니라 실제 결과를 갖게 됨.

원본 단일PPO, KOSPI)는 전부 임베딩 기반 밀집 행동공간이고, "실패 미재현" 두 경우(크립토 EIIE,
미국주식)는 전부 원시 가격윈도우 방식**이라는 패턴이 이 프로젝트 데이터 안에서 이미 두 번
반복된다. "시장이 바뀌면 실패가 사라진다(regime 가설)"보다 **"상태표현이 바뀌면 실패가
사라진다(architecture 가설)"는 설명이 지금 가진 증거로 더 잘 뒷받침됨** — 다만 market과
architecture 두 변수가 이 실험에서 완전히 얽혀 있어(confound), 순수하게 market만 격리하려면
미국주식에도 임베딩 백본을 새로 구축해 재검증해야 한다(이번 범위 밖, 향후 과제).

| 미국주식(§22) | 원시 가격윈도우 | 1.498 | 1.473 | 실패 없음(동률) |
| **미국주식(신규)** | **임베딩** | **1.252** | **1.477** | **중간 정도 저조** |

valid에서도 같은 방향(임베딩 PPO Sharpe 1.382 vs 등가중 1.533, 원시버전은 두 구간 다 등가중과
동률이었음). **결정적 단서는 턴오버**: 임베딩 버전 평균 턴오버가 스텝당 9.2~9.4%인데 원시
가격윈도우 버전은 0.38%(24배 차이) — 크립토 v1(§1)의 원래 발견("턴오버가 알파를 태운다")과
정확히 같은 메커니즘이 재현됨. 임베딩 기반 상태가 정책을 더 불안정하게(더 자주·크게 리밸런싱)
만드는 것으로 보인다.

**해석**: confound가 부분적으로 풀렸다 — 같은 시장에서 상태표현만 바꿔도 성과가 "동률"에서
"명확히 저조"로 이동해, **architecture가 실제 인과적 요인임이 확인**됐다(턴오버라는 구체적
메커니즘까지 확보). 다만 크립토(-4.209)·KOSPI(0.100 vs 1.043)만큼 파국적이지는 않아, 실패의
**정도**는 market/레짐이 함께 조절하는 것으로 보인다. 깔끔한 이분법("architecture 아니면
market")보다 "architecture가 방향(왜 실패가 생기는가), market/레짐이 정도(얼마나 심한가)를
설명한다"는 더 정교한 결론이 데이터로 뒷받침된다.
